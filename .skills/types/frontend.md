# Web 前端项目规则模块

项目规则必须补充框架、包管理器、路由、状态、组件库、请求层、生成链路、测试工具、构建命令和设计系统。本文件只保留通用前端检查。

## 改动前检查

- 确定页面、路由/菜单、权限、状态、请求、生成 API、组件、主题和配置的事实源。
- 搜索同类页面、组件、hook、store、请求适配和测试。
- 确定接口是项目生成代码、手写适配层还是统一请求层提供；不要直接跨越项目错误处理和鉴权机制。

## 实现约束

- 优先复用项目封装组件、设计 token、交互模式和统一反馈机制。
- 不为局部需求绕过公共 loading、错误、权限、校验、下载或请求状态管理。
- 路由、菜单、缓存、权限、页面入口和状态同步应一起检查。
- 生成 API 默认通过生成链路更新；手写补丁必须是项目规则明确允许的适配层。
- UI 改动至少覆盖空态、加载、失败、权限、窄屏或目标终端需要的交互状态。

## 验证优先级

1. 类型检查和受影响单元/组件测试
2. 路由、请求、状态或交互 smoke
3. 生成、构建或静态检查
4. 浏览器端到端或视觉验证，适用于用户可见关键流程

## 不要做

- 不手改生成 API 作为长期方案
- 不复制请求层已处理的通用提示或鉴权逻辑
- 不因为统一风格而大范围重写历史组件
- 不只验证静态渲染而忽略加载、失败、提交防重和状态同步
