# 后端项目规则模块

项目后端规则必须补充具体框架、解决方案入口、分层边界、数据访问、配置、测试命令和部署限制。本文件只保留跨后端项目通用的检查。

## 改动前检查

- 确定接口、领域、应用服务、持久化、后台作业、认证、缓存和配置的事实源。
- 判定是纯逻辑、数据库行为、HTTP 契约、异步任务还是外部通道变更。
- 确定 DTO/请求/结果模型应放在哪个公共层，而不是临时定义在服务实现中。
- 阅读相邻接口、验证器、异常映射、事务与测试样例。

## 高风险路径

- 数据迁移、事务、并发锁、幂等、状态机、定时任务和消息消费
- 认证、授权、当前用户上下文、令牌、权限缓存和多租户
- 公开 API、错误语义、枚举序列化、分页、文件上传下载和 OpenAPI
- 外部 HTTP、支付、消息、邮件、存储、回调和密钥配置

触及任一项时，在 spec 写明兼容、回滚、验证环境和人工/种子回归边界。

## 验证优先级

1. 受影响单元测试或纯逻辑验证
2. 应用/HTTP 集成、契约或数据库测试
3. 服务启动、迁移或依赖注入 smoke
4. 外部服务的明确 manual 或 seeded regression

不把依赖真实环境的测试伪装成默认自动化测试。后台/异步路径不应隐式依赖当前 HTTP 请求上下文；项目规则必须规定用户、租户和追踪信息的显式传递方式。

## 不要做

- 不在业务服务中复制公共 DTO、参数或结果模型
- 不通过手改生成的 API/ORM/OpenAPI 文件逃避源头修复
- 不在未定义迁移和回退时更改数据契约
- 不在后台任务中隐式读取仅存在于当前请求的上下文
