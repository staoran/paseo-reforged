# 桌面应用项目规则模块

项目规则必须补充桌面运行时或框架、UI 入口、后台/worker 入口、进程间通信、原生能力、文件与权限边界、打包/签名/发布命令和目标操作系统。本文件只保留跨桌面项目通用的检查。

## 类型边界

- `desktop` 表示以本地窗口、托盘、系统菜单或其他桌面 GUI 为主要交付形态的应用，无论采用安装包还是便携运行；Electron、Tauri、Qt、MAUI、Flutter Desktop 等都可归入此类。
- 只有实际存在对应代码层时才叠加 `frontend` 或 `backend`：嵌入式 Web UI 可启用 `desktop + frontend`，独立本地 HTTP/RPC 服务可启用 `desktop + backend`；普通后台 worker 仍属于桌面运行时边界。组合不是把一份代码重复归类。
- 纯命令行下载器或无 GUI 工具不应启用 `desktop`，应在项目规则中使用 `other` 并写明 CLI 约束，待规则包提供专门 CLI 模块后再迁移。

## 改动前检查

- 确定窗口/页面入口、主进程或宿主进程、预加载/桥接层、后台 worker、IPC/command handler 和生命周期事实源。
- 确定文件系统、剪贴板、屏幕捕获、系统通知、外部协议、网络、代理、凭据和原生权限的封装边界。
- 确定用户数据目录、缓存、临时文件、导出文件和升级迁移策略；区分开发目录、安装目录与可写目录。
- 确定目标操作系统、架构、打包器、签名/公证、自动更新和发布产物的事实源；不能把 Web 开发服务器当作桌面发布验证。
- 搜索相邻的 IPC/bridge、权限声明、窗口配置、异常处理、取消/进度回传和端到端 smoke 测试。

## 实现约束

- UI 层通过项目定义的 preload、bridge、command 或 IPC API 使用原生能力；不要在渲染层绕过边界直接获得高权限运行时对象。
- IPC 输入、输出、错误和取消语义必须可验证；文件路径、外部 URL、命令参数和用户可控内容按项目安全规则校验。
- 保持窗口生命周期、单实例、托盘/快捷键、休眠恢复和后台任务的既有语义；长任务要有进度、取消、失败和重试边界。
- 不把用户数据写入安装目录，不把密钥或长期凭据打进前端 bundle；升级、卸载和回滚不得无记录地删除用户文件。
- 涉及截图、OCR、下载、剪贴板或系统 API 时，明确权限失败、不可用平台和无权限回退行为；平台差异不能由浏览器结果推断。
- 生成的 manifest、权限清单、安装器配置和签名产物按项目生成链路更新，不手改生成文件作为长期修复。

## 验证优先级

1. 纯逻辑、序列化、IPC/bridge、worker 和取消/进度单元测试
2. 开发运行时 smoke：启动、窗口关闭/恢复、IPC 错误、文件读写和核心用户流程
3. 目标操作系统的构建、打包、安装/升级或启动检查（适用时）
4. 目标 OS/架构矩阵的人工或自动化验收，覆盖权限拒绝、路径、网络、休眠恢复和失败回退

不能运行目标 OS 或签名/安装验证时，记录未执行原因、替代证据和残余风险；不能以浏览器页面渲染通过替代桌面验收。

## 不要做

- 不把桌面 GUI 默认当作纯 Web 项目，也不把本地 worker 默认当作独立 API 项目。
- 不绕过 preload、bridge、IPC 或权限封装直接调用高权限原生 API。
- 不只启动 Web dev server 就宣称桌面功能通过。
- 不直接修改打包器生成的 manifest、安装器或签名文件来隐藏源头配置问题。
- 不在未确认用户数据目录、升级策略和回滚边界时删除、迁移或覆盖本地数据。
