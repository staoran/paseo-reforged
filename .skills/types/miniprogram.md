# 小程序与移动多端项目规则模块

项目规则必须补充目标平台、页面注册、端侧路由、权限、网络适配、构建命令、原生能力、组件库、测试工具和真机/模拟器策略。本文件只保留通用多端检查。

本模块覆盖小程序、移动端多端框架和移动端原生容器；具有本地窗口、托盘或桌面系统集成的 GUI 工具使用 `desktop`，不因共享 Web 技术栈而启用本模块。

## 改动前检查

- 确定页面注册和 tabbar 的事实源，不只看文件树。
- 确定登录、权限、存储、网络、上传下载、平台差异和生命周期入口。
- 确定 API 是否来自生成客户端及其运行时适配层。
- 对涉及平台能力的变更，区分可控封装和必须在端上验证的原生行为。

## 实现约束

- 复用项目已有跨端组件、路由、请求、存储和平台 adapter。
- 不能把 H5 行为假定为小程序、原生容器或不同厂商运行时的行为。
- 修改 tabbar、登录拦截、隐私授权、分享、文件选择、支付、更新或原生 bridge 时，写明目标端和回退行为。
- 页面注册、manifest、平台配置和生成 API 属于事实源变更，必须做语法与目标端影响检查。

## 验证优先级

1. 纯逻辑、请求、store、adapter 单元测试
2. 组件公开 props、emit、slot 和绑定结果测试
3. 路由、登录、表单和页面流程 smoke
4. 对应平台构建和端上人工/自动化验证

## 不要做

- 不将一个端的运行结果泛化为所有端
- 不仅因页面文件存在就认定页面已注册
- 不跳过原生权限、隐私、上传、支付、更新等失败路径
- 不直接手改生成客户端规避契约更新
