# 项目规则与文档约定维护

## 内容归属

| 内容 | 权威落点 |
| --- | --- |
| 项目身份、默认协作语言、代码/文档命名语言、命令、事实源、类型模块、执行门禁、文档布局 | `.skills/project/PROJECT_RULES.md` |
| 只对某个目录树生效的稳定规则 | 目标目录最近的 `AGENTS.md`；根入口只保留路由 |
| 项目专属任务模板、字段或文档目录约定 | 项目登记的 templates 目录，并在 `PROJECT_RULES.md#文档布局` 路由 |
| 通用包 workflow 的项目增量 | `CUSTOM_SKILL_OVERRIDES.md`，不写进本文件 |

任务目录默认格式为 `<编号>_<任务标题>/`。编号来源、标题语言、允许字符与清理规则由 `PROJECT_RULES.md` 声明；除非项目明确改变该格式，不在目录名追加项目集合、状态、负责人或日期。跨项目信息保留在父级 Spec 的项目注册表。

## 维护流程

1. 从 README、manifest、CI、构建/测试配置、源码入口和现有规则确认事实；命令至少有一次可定位证据。
2. 检查根与子目录 `AGENTS.md` 的优先级，决定修改项目规则还是最近目录规则。相同规则只保留一个权威正文。
3. 提案写明原规则、目标规则、适用范围、冲突、迁移影响和验证。语言规则要分别说明协作输出、代码标识符、文件名和任务/文档标题。
4. 获批后只改相关字段；未知项保留 `UNCONFIGURED`，不从其他项目复制技术事实。
5. 验证 INDEX/入口路由、类型枚举、文档路径、任务目录样例、表格和命令证据；规则影响现有任务时说明是否迁移，默认不批量重命名历史任务。

## 不可覆盖边界

- `enabled_workflows` 只能控制可选增强模块，不能关闭 SDD-RIPER 核心闭环或 `cross` 安全流程。
- 更近或更严格的 `AGENTS.md` 继续优先；内容级合并不能静默放宽门禁。
- 项目任务模板不能重新引入多重事实源；职责仍以 `core/durable-context.md` 为准。
- 根 `AGENTS.md` 保持最小路由，不承载技术栈手册、完整命令表或项目 Skill 正文。
