# 跨任务协作工作流

本模块管理同一项目或同一任务包内多个会实施的任务、子任务、执行者或会话之间的协作。它不同于 `cross-project.md`：前者处理工作单元间的共享上下文和交接，后者处理独立项目间的公开契约与发布顺序。运行模型已判定为“查询”的同项目只读评审或调查不加载本模块，可在同一响应中共享内联结论。

## 与相邻工作流的边界

- `task-decomposition.md` 负责创建最小工作单元、定义依赖图和判定能否拆分；本模块只负责已定义单元的并行、交接、共享写入和合并。
- `task-tracking.md` 负责创建并维护 task plan、findings、progress 和 handoff 等持久任务包；本模块在这些既有文件中登记协作合同与合并结果，不新建第二套进度体系。
- `cross-project.md` 在涉及多个独立项目时优先负责授权范围、父级契约、Provider/Consumer 和发布顺序；本模块仅协调各项目内部或父级任务包内的子任务。

## 触发与升级条件

- 一个主任务拆分为两个以上独立或半独立子任务
- 多个会话、执行者或自动化流程会接续同一任务
- 子任务共用 spec、事实源、测试底座、配置、生成链路或决策
- 需要将调查、实现、测试、审查或发布分别委派并最终合并

若协作尚未启用 tracking，只有同会话、只读且不形成交接的查询可以保持内联。出现实施、共享写入、跨会话继续、交接、独立验收阶段或需要持久当前状态时，先停止协作动作，按 `task-tracking.md` 建立完整任务包和 task plan；完成后才可创建子任务、委派或更新共享记录。

## 协作协议

1. 委派不转移主任务对范围与方案裁决、冲突处理、结果整合和最终验证的责任；指定协调者可以执行合并动作，但主任务必须亲自复核并作最终整合裁决，最终整合责任不可转移；执行者只在已授权的子任务与路径内实施；每个共享写入点有且只有一个负责人；主任务复核来源、最终 diff、依赖和验收/测试证据后才可宣布完成。用户只要求说明责任和完成门禁时，回答必须逐项明确这四项；只写“检查共享写入”或“验收通过”不满足完成标准。主任务保留唯一的主 spec、task plan、依赖图和完成裁决。
2. 每个子任务使用唯一 ID；task plan 只记录索引、依赖、所有者、共享资源负责人、当前状态和 progress 锚点。
3. 共享事实、契约和已采纳决策只在主 spec 或明确的共享文档维护；未验证假设和调查写入 findings。
4. 子任务合同只写入 subtask；实际变更、验证、失败、残余风险和下一步只写入 progress。
5. 协调者将已核验结论合并到主 spec，不复制调查或执行正文。
6. 协调者在合并与完成裁决前执行第 1 条责任门禁，并另行核对范围和文档同步。

## 子任务交接合同

使用 `.skills/templates/subtask.md` 记录完整合同；主 `task_plan.md` 仅保留索引、依赖、所有者、共享资源负责人、当前状态和 progress 锚点。

```text
任务 ID：...
目标与非目标：...
依赖与输入版本：...
允许修改的路径：...
禁止修改的共享资源：...
输出交付物：...
验收证据：...
计划风险与回退：...
阻塞时升级对象：...
```

## 🔴 CHECKPOINT：并行或交接前

开始并行执行或交接前，必须确认：每个任务有唯一目标和允许修改路径，依赖和事实源版本已固定，共享写入点有唯一负责人，合并标准与验收证据明确，未授权范围未被纳入。任一项缺失时，保持串行或先补主任务计划。

## 合并规则

- 调查结论以来源和可复现证据合并，不按执行者数量投票。
- 共享接口、全局配置、生成物、迁移、任务索引和长期知识由指定协调者写入。
- 两个子任务对同一行为提出不同方案时，记录冲突，回到主 spec 的目标、约束与验收裁决；不能通过最后写入者覆盖。
- 子任务发现不在范围内的问题，登记候选待办或交回主任务，不擅自扩展。

## 失败处理

| 触发条件 | 一线处理 | 兜底 |
| --- | --- | --- |
| 子任务输入或依赖变更 | 标记受影响子任务并重新读取主 spec | 暂停后续任务，更新依赖图和 checkpoint |
| 多个任务修改同一共享文件 | 停止并行写入 | 由协调者合并，必要时拆分为串行步骤 |
| 子任务结论相互矛盾 | 比对事实源、progress 证据和验收 | 请求项目决策者裁决，不静默选择 |
| 交接缺少验证或恢复信息 | 退回补齐交接合同 | 不将任务标为可接续或已完成 |

## 反模式

- 把多个子任务的聊天摘要当作唯一协作记录
- 让每个子任务各自维护相同的事实、契约、状态或任务索引
- 未定义共享资源负责人就并行修改
- 仅汇报文件清单，不汇报验收证据、风险和下一步
