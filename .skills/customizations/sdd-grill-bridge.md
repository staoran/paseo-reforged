# SDD 与 Grill 的组合路由

本模块只定义已加载的全局 SDD Harness 与 `grill-me.md` 的转换协议：Grill 位于 **Research -> Plan** 之间，收紧会改变方案或验收的歧义，不替代 spec、执行门禁或验证。

## 输入与输出

- 输入：用户目标、现有 spec、项目规则、codemap、关键上下文、已知事实和关键未决项。
- 输出：已确认目标/边界/决策/验收写入 spec；待查事实和工作假设写入 findings；范围外线索写入候选待办。工作假设必须带验证点或升级条件。

是否触发及排除场景只以 `../workflows/grill-me.md#何时触发` 为准。本桥接只负责转换：先分开可查事实与决策歧义，只把后者交给 Grill；结论按输出规则回写，不保留独立访谈记录。

## 🔴 CHECKPOINT：转入 SDD Plan

只有目标/非目标可区分、事实有来源、关键未决项已决、验收可执行、风险与回退明确时才能进入 Plan；否则继续调查或请求决策。

## 失败处理

| 触发条件 | 一线处理 | 兜底 |
| --- | --- | --- |
| 只有技术事实未知 | 回到 Research | 不启动访谈式 Grill |
| Grill 与既有 spec 冲突 | 记录来源与影响 | 停止 Plan/Execute，等待裁决 |
| 问题超出授权 | 记录候选待办 | 不创建未授权任务或跨项目改动 |

## 项目 override

强制 Grill 领域、追问上限、决策来源和默认策略写入 `.skills/project/CUSTOM_SKILL_OVERRIDES.md`；override 不能取消检查点或把可查事实改成用户问答。

## 反模式

- 对所有复杂任务强制长访谈
- 把可查事实反问用户，或在 spec 外维护决策
- 未通过检查点就进入 Plan/Execute
