## 1. 目标与完成契约

- 当前理解：打开 Changes 时不应同步挂载全部差异正文；从轮次变更卡片定向打开时只展开目标文件，后续聚焦请求不应让无关文件正文重新参与渲染；相同比较条件下复用已有 diff 数据。
- 核心目标：移除 Changes 首次打开和卡片重复聚焦中的秒级主线程阻塞，同时保持文件头、展开/收起、目标滚动和 review 行为可用。
- Done Contract：无目标的 Changes 初次打开只显示文件头；带 `focusPath` 的初次或后续请求只展开并聚焦目标文件；仅变化 `focusRequestId` 不重建结构性 diff 列表；相同 uncommitted compare 不再因 working-diff tab scope 创建第二份订阅；定向 browser 测试、真实 Electron 性能复测和项目静态检查通过。

## 2. 范围与事实

- 范围内：`WorkingDiffPanel` 初始/定向展开策略，`SharedDiffView` 的 focus 与结构依赖拆分，working diff query 复用，browser component 回归测试和真实 CDP 性能复测。
- 范围外：行级虚拟化、diff 协议或 daemon 改动、Changes 视觉重设计、其他面板重构、0027 Mermaid 并行改动。
- 当前任务单元：在现有 Changes/轮次文件卡片链路内完成一个可独立验证的性能缺陷修复。
- 轻量评估：`standard`；涉及组件状态、共享 diff 视图、query identity 和 browser 测试，但公共边界清楚且不需要 Heavy Spec。
- 已确认事实：真实 Electron 中 17 文件、620 行 diff 冷打开约 5.8 秒，暖缓存仍约 3.0-3.2 秒；首次 React mount 约 2057ms，后续批次约 806ms；展开时 working panel 约 7757 个 DOM 节点，折叠后 154 个；折叠后卡片聚焦降至约 564ms。`expandedPaths=null` 当前代表全部展开，`focusRequestId` 被装入完整 `mode`，working tab 的 scoped query 与轮次卡片 canonical query 不同。
- `grilling` 结论（如使用）：未使用；根因与批准方案已由用户确认。
- 风险与未知：默认折叠改变既有初始展示；定向请求需确保目标存在、重复请求可重新滚动；移除 query scope 必须保持不同 compare（base/whitespace）仍由 canonical key 隔离；性能断言不得使用脆弱的绝对时间阈值。
