## 1. 目标与完成契约

- 当前理解：Electron 软件退出时，记录当时仍有未归档 `running` 根 Agent 的 workspace；下一次启动后在对应会话元数据行原有绿色机器人位置显示黄色机器人，用户打开该会话后标记消失并恢复实时驻留 Agent 的绿色机器人语义。
- 核心目标：为“退出期间可能继续工作的会话”提供一次性回访提示，不改变 Agent 生命周期、现有侧边栏状态分组或完成未读提示。
- Done Contract：正常 Electron 退出会持久化所有符合条件的 `serverId + workspaceId`；重启后的项目分组、状态分组和置顶行均在驻留 Agent 指示器位置显示黄色机器人，即使当前没有驻留 Agent 也显示；打开对应 workspace 后仅清除该标记，并按当前驻留 Agent 数量恢复绿色机器人或隐藏指示器；非 `running`、已归档或子 Agent 不产生标记；定向 Vitest、Desktop/App typecheck、lint、格式与差异检查通过。

## 2. 范围与事实

- 范围内：Electron 退出前通知、App 本地同步持久化、活跃根 Agent 投影、侧边栏 workspace 元数据行黄色机器人标记、打开 workspace 后清除、精确测试。
- 范围外：daemon/协议字段、Agent 运行与恢复语义、系统通知、移动端后台生命周期、现有绿色未读完成态和状态分桶。
- 当前任务单元：在桌面退出边界保存一次性 workspace 身份集合，并将其作为不参与分组的独立 UI 提示消费。
- 轻量评估：`standard`；目标单一，但跨 Electron 退出生命周期、持久化和共享侧边栏行，需要多文件验证。
- 已确认事实：`createQuitLifecycle()` 是所有正常退出路径的统一入口；现有 `quitting` 事件只在停止托管 daemon 时发出且驱动退出遮罩，不能复用为无条件记录事件；Electron Web 的 AsyncStorage 最终同步写入 `window.localStorage`；workspace 行共享 `SidebarWorkspaceRowContent`；活动 workspace 可由 `useActiveWorkspaceSelection()` 观察；根 Agent 判定已有 `isWorkspaceRootAgent()`。
- `grilling` 结论（如使用）：`N/A`；需求边界足够明确。
- 风险与未知：Electron 主进程事件到 renderer 的退出时序需要保持足够早；多窗口必须合并而不是互相覆盖；workspace 身份不能只拼接后再反向解析；现有工作区有大量用户改动，实施时只叠加本任务差异。
