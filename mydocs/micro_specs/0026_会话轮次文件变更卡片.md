## 1. 目标与完成契约

- 当前理解：最新一轮 assistant 会话完成后，在回复末尾显示本轮涉及的有效文件变更；卡片顶部汇总文件数、增加行和删除行，下面默认显示 3 个文件，可展开其余文件，点击文件打开 Changes 差异页并聚焦该文件。新一轮开始时不再展示上一轮卡片，新一轮完成后只展示新的卡片，历史轮次不保留可能失效的差异入口。
- 核心目标：让用户在当前会话结束点直接看见并进入本轮仍然有效的代码变化，同时避免把会随 working tree 漂移的旧 diff 快照散落在历史消息中。
- Done Contract：仅最新完成轮次、且该轮存在当前有效 working diff 时渲染卡片；汇总数值等于卡片文件行统计之和；默认最多 3 行、展开/收起稳定；每行点击打开 `working_diff` tab 并通过 `focusPath` 聚焦；下一轮运行时旧卡片消失，完成后以新轮次文件替换；定向测试、typecheck、lint、格式和 Web 视觉验收通过。

## 2. 范围与事实

- 范围内：`packages/app` 的最新完成轮次投影、live checkout diff 订阅、文件卡片 UI、展开状态、Changes tab 聚焦导航和定向测试。
- 范围外：daemon/protocol 新字段、持久化历史 turn diff、turn-start/turn-end Git 快照、已提交或已回滚文件的历史 diff、Undo/Review 按钮、shell 命令内部无法由结构化工具记录识别的隐式文件写入。
- 当前任务单元：会话轮次文件变更卡片；`parent spec=N/A`。
- 轻量评估：`standard`；功能跨越 stream 投影、diff query、footer 呈现和 workspace tab intent，但复用现有接口，不改变公共协议。
- 已确认事实：`TurnFooter` 的 auxiliary footer 只对应最新完成轮次，历史轮次走独立的 `CompletedTurnFooterRow`；`ToolCallDetail` 已结构化提供 `edit/write.filePath`；`useCheckoutDiffQuery()` 已提供当前每文件 `additions/deletions/hunks`；`WorkspaceWorkingDiffTabTarget` 已支持 `focusPath/focusRequestId`。
- 已确认的统计语义：文件集合取最新轮次内成功的结构化 `edit/write`，再与当前 working diff 求交集；行数展示这些文件的当前 working diff 统计，而不是 turn-start/turn-end 的精确增量。这样差异入口始终有效，也符合“更早变化被最新覆盖”；若以后要求精确轮次增量，需要升级为服务端 Git 快照与协议方案。
- 与现有改动的关系：任务 `0016` 正在修改 `agent-stream/layout.ts/view.tsx`，任务 `0023` 正在修改最终回答/footer 可见信息；实施时只在当前工作树上做增量，不回退或重写两者已有改动，并优先把新投影与卡片放到独立文件。
- 风险与未知：绝对路径、Windows 分隔符与 workspace-relative diff path 需要统一；重复编辑必须去重；新一轮需重置展开状态；非 Git workspace、当前已回滚文件和 diff 查询失败时应静默不显示；结构化工具之外的 shell 写文件不在本次可靠识别范围内。
