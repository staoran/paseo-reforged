### 版本策略可行性复核

| 候选格式           | 当前支持 | 排序与发布结论                                                                                     |
| ------------------ | -------- | -------------------------------------------------------------------------------------------------- |
| `0.2.5.1`          | 否       | 非 SemVer；版本脚本、tag 环境解析和 Native build version 均拒绝，release notes 的 tag 解析也会失败 |
| `0.2.5-beta.N`     | 部分支持 | 产物链、beta channel、tag 与 changelog 均支持；需让 `release:beta:next` 可从稳定基线启动 `beta.1`  |
| `0.2.5+reforged.N` | 否       | build metadata 与 `0.2.5` 排序相等，无法驱动更新；当前 Reforged release parser 也拒绝              |
| `0.2.6-beta.N`     | 支持     | 当前完整支持且排序高于 `0.2.5`，但已被用户否决，因为不应占用上游下一 patch 版本                    |

- 推荐策略：采用 `UPSTREAM_X.Y.Z-beta.N`；`N` 表示同一上游基线下第 N 次 Reforged 公开测试版。当前没有 `v0.2.5-beta.*`，因此首版为 `0.2.5-beta.1`；采用上游 `0.2.6` 后重置为 `0.2.6-beta.1`。
- 正式渠道策略：采用 `UPSTREAM_X.Y.Z-reforged.N`；当前未来首个正式渠道版本为 `0.2.5-reforged.1`，采用上游 `0.2.6` 后重置为 `0.2.6-reforged.1`。该格式是合法 SemVer prerelease，当前 parser、promote、GitHub stable gate 与 Electron stable updater 尚不支持把它作为正式渠道发布；本轮只登记策略与前置条件，不解除 stable gate，也不实现或发布正式版。
- 不推荐把 `N` 定义为原始 Git commit 数：当前 `v0.2.5..HEAD` 分别为全部 `54`、first-parent `53`、排除 merge `49`，而采用 merge `70613999a..HEAD` 仅为 `2`；changelog 和 release commit 还会继续改变计数，无法得到稳定、唯一的修订号。
