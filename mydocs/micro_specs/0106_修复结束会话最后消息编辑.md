## 1. 目标与完成契约

- 当前理解：自然结束或手动停止后，最后一条纯文本用户消息有时不显示 Edit；即使显示，提交编辑也可能以“不是最新可重放纯文本消息”失败
- 核心目标：让普通和 Steer 的纯文本提交路径保留 `text_only` replay proof，并让 Pi Stop 后迟到的 provider marker 仍归属原始 canonical 用户行，使 idle 的最后纯文本用户消息可显示 Edit，原位编辑正确启动 replacement turn
- Done Contract：服务端 E2E 验证自然结束的消息可完成原位编辑且使用 provider-native ID；Pi provider 单测覆盖 Stop 后和下一轮开始后到达的 marker，验证不重复追加、不串写 client/provider ID；Browser E2E 验证现有自然结束和 Stop 后恢复路径可编辑并出现 replacement 消息；附件、运行中和未知历史门禁保持 fail-closed

## 2. 范围与事实

- 范围内：`streamAgent()` 和 accepted Steer 提交 canonical 用户行时的 replay proof 传递；Pi submitted-entry marker 的稳定关联；服务端、Pi provider 与 Browser Edit 回归覆盖
- 范围外：放宽 Edit eligibility、改动协议或 provider rewind 语义、重启 `6767` daemon、修改无关 `0104`/`0105` 或 protocol 工作树改动、commit、push、发布
- 当前任务单元：普通纯文本发送使用 `streamAgent()`；自然结束和 Stop 后恢复共享 canonical replay proof 缺失问题。审查确认 Pi 的 submitted-entry marker 可在 Stop 后迟到，旧实现会从当前 active state 错取关联；默认 Steer 路径也漏传 replay proof
- 轻量评估：`standard`，涉及服务端与浏览器回归，但修复预计为单一字段传递
- 已确认事实：`session.ts` 对纯文本消息传入 `replayKind: "text_only"`；`streamAgent()` 创建的 `pendingRun` 已保存该值，但调用 `recordSubmittedPrompt()` 时未传递；`startForegroundTurn()` 已正确传递该值
- 已确认事实：`packages/server/src/server/daemon-e2e/edit-last-user-message.e2e.test.ts` 在当前 HEAD 稳定 RED，编辑请求返回 `validation` / `The edit target is not the latest replayable text user message`
- 已确认事实：App 模型要求最后消息的 `replayKind === "text_only"`，因此缺失时隐藏 Edit 是预期 fail-closed 行为，不应在 App 侧放宽
- 已确认事实：Pi extension 在用户 `message_end` 后，等 assistant `message_start` 或 `turn_end` 才发送 submitted-entry marker。`interrupt()` 会清空 active turn/client ID；marker 若此后到达就会失去关联，若 B 已开始则可能错绑 B
- 已确认事实：Pi 的 user `message_end` 与 extension 的同一事件可作为稳定序列起点。extension 和 session 共享单调 marker sequence，session 在 `message_end` 时捕获关联，marker 只按 sequence 消费，缺失或过期关联继续 fail-closed
- 审查新增事实：session 仍以文本从已 accepted Steer 队列认领 `clientMessageId`。若初始 prompt A 与 Steer B 文本相同，且 A 的 `message_end` 在 B 被接受后才到，A 会被误认领为 B；必须按 Pi 用户消息的顺序消费初始 prompt 与 Steer，而不再用文本猜测
- `grilling` 结论（如使用）：`N/A`
- 风险与未知：须确保 provider-native `providerMessageId` 的既有映射保持不变，避免回退 `0067` 已修复的 ID 翻译
