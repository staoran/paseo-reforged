## 1. 分类方法与结论

| 分类          | 判定标准                                                                                          | 本次实例                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 同源修复冲突  | 同一原始修复被 cherry-pick 或随不同分支演进，两侧要修同一根因，Git 因提交拓扑或上下文变化不能识别 | OpenCode `#5587` 的模型切换测试；Sonnet `#5583` 已合入后与 Haiku 增量相遇                 |
| 真实意图冲突  | 同一对象的最终合同不同，不能直接选两者并存                                                        | CI 自动/手动触发、发行身份、已发布 fork Usage 协议的保留、时间戳显示语义                  |
| 并列编辑冲突  | 相邻位置新增不同能力，两侧意图可以同时成立                                                        | 选择工具栏切换回归与图片复制测试；Activity host 定位与虚拟列表 ref；类型 import           |
| 演进替换冲突  | 上游搬迁实现职责，本地旧实现或旧测试还留在原位置                                                  | `getUsageReference()` 迁到 `usageSession()` 与账号插件；旧 Usage RPC 被上游按“未发布”删除 |
| 派生物冲突    | 值取决于最终输入，不能靠选择一侧保证正确                                                          | npm lockfile、Nix 哈希                                                                    |
| 交互冲突/风险 | 无文本冲突，组合后却丢入口、改变语义、错用状态或破坏跨版本行为                                    | Explorer 新宿主没有传递 runtime actions；新插件最低版本高于保留的 fork 版本               |

分类可以叠加。例如 OpenCode 测试大块同时包含同源模型修复和旧 Usage 测试，不允许给整个文件贴一个标签后整侧覆盖。

**主要判断：**

- 不能用 `ours`/`theirs` 整文件批量解决。版本、法语、provider 测试尤其危险
- 同源修复优先去重。`#5587` 两侧核心实现相同，没有依据说其中一侧算法更好；以上游当前测试结构为骨架更便于承接后续改动
- 上游 Haiku 与新 OpenCode v2 回合管理是更完整的增量；本地 Sonnet 与 variant 合同继续成立，应保留其覆盖而非重做一份
- 本地 Activity、选择操作、runtime 回收、消息时间戳不是旧版上游功能的替代实现，不能因上游更新删掉
- 旧 0127 的“合并时保留原版本号”不能无条件沿用：这次已有内置插件要求 `>=0.11.0`
- 本次最先决定的事项是版本与插件门槛、Usage 跨版本合同、CI 触发策略；先机械清标记再处理这些，会得到能编译但不能正确升级的组合

## 2. 本地 Reforged 的意图

### 2.1 独立产品与发行轨道

0119/F42、`cfa0db9ff`、`28e7e6638` 把 App、Electron、CLI 的用户可见名称、安装标识、下载和更新源归到 Reforged。当前发行号是 `0.10.0-beta.3`，不是上游发行号的别名。内部 `@getpaseo/*` 包名保持兼容，但 workspace 版本与内部引用必须统一。

`CHANGELOG.md` 是 fork App 的 What's new 与 Release Notes Sync 的输入。本地希望用户看到实际收到的 Reforged 版本、测试构建与增强能力；将上游正式发行标题直接放到最上方，会把上游发行事实误呈现成 fork 的发行事实。

### 2.2 可控的 CI 成本

`507e66ffb` 明确取消自动浏览器 E2E、Desktop Packages、Nix 和 Nix hash 工作流触发，保留手动运行。此处是已交付的流程选择，不是本地忘了上游的触发器。合入源码与恢复自动打包是两个决策。

### 2.3 聊天操作、整轮折叠与阅读位置

- F11/F12：选中 assistant 文本可继续提问、开新窗口、保存 prompt preset；`28937ae61` 修复保留面板切换后旧工具栏残留。非活动会话不应操作上一会话的选区
- 0121/F07：Codex 的显式 `final_answer` 结束 Activity，过程行折叠为稳定 host；原始消息仍可搜索、跳转和复制。`messageHostIds` 负责从原消息找到折叠后的行
- F19/F20/F24：权限模式风险色、Markdown 加粗修复、Windows 文件链接与行号属于独立合同，不能被一般上游 UI 重构覆盖

### 2.4 Workspace 状态与 runtime 回收

0124/0125 把“任务工作状态”“未读 attention”“daemon 持有 runtime”“历史未关闭记录”分开。闲态回收只关闭 runtime，保留记录；“关闭并保留记录”确认关闭后再移除当前标签。普通根标签 X 仍归档，子标签普通关闭仍只改布局。

驻留数字来自当前连接的权威 Agent 目录，离线或目录未同步时隐藏。`runtimeAttached` 区分 live 会话和橙色历史记录。不能拿 workspace Working/Ready 推断进程存活，也不能把 provider 子线程算成独立 managed runtime。

### 2.5 时间戳准确与重试可见

`c1e22bf5e` 让侧栏时间取 workspace 内最新用户/assistant 消息，排除标题、状态、读操作和纯工具事件；`0fdb2c68a` 补齐 durable/replay/resume 的时间回填和持久化。用户读取、关闭、恢复会话不能把旧对话显示成“刚刚”。

F03 的 Codex retry 状态只属于当前根回合，不成为 timeline 文本，恢复或终止时清除；旧回合与子线程的重试不污染当前会话。

## 4. 建议决策与取舍

### D1 版本与插件门槛：不能直接沿用 0.10.0-beta.3

**本地意图：**保留独立 beta 身份和统一 workspace 版本。**上游意图：**用 `0.11.1` 表示具备新插件 API 的宿主。

已确认 `codex-usage-source`、`muse-provider` manifest 要求 `>=0.11.0`，`PluginRuntime.startBuiltinPlugin()` 会执行 `assertPluginCompatibility()`。当前版本的稳定核心是 `0.10.0`，也不满足门槛。保留现有号会拒绝加载这两个内置插件；仅删除 prerelease 检查不能解决。

**已确认并实施：**使用 `0.11.1-beta.1`，统一所有 manifest、lock 与内部依赖。该版本对应此次代码底座，满足插件的稳定核心门槛；改开发版本不自动授权 npm/GitHub 发布。产品名称、安装 ID、更新仓库继续使用 Reforged。

**替代方案：**若必须保持原版本，需要逐个核实并降低 fork 内置 manifest 门槛。此方案仍让 registry 的 `>=0.11.0` 插件拒绝当前宿主，且让用户难以判断兼容性，维护成本更高。不得跳过所有插件兼容校验。

这是发行身份与 API 版本关联的真实分歧，不是“数字取较大者”。这一次建议优先采用代码匹配的新版 beta 身份，理由是实际门槛已经存在。

### D2 Changelog：保留 fork 发行事实，合入功能素材

**本地意图：**历史 Reforged beta 可追溯。**上游意图：**展示正式 0.11.1/0.11.0 及此前官方版本的发行内容。

**建议：**保留本地已有发行条目；新集成内容整理为下一次 Reforged 说明，明确上游基线 `ab10a6694`。不能把上游大块挪到本地 beta 标题下后，把共同的 Added/Fixed 尾部误接成上游 `0.10.0` 正文，也不能将未发布 fork 标成正式 `0.11.1`。

上游的新功能说明更完整，适合作为素材；发行归属由本地事实决定。beta 单条累计策略可用于今后的新系列，保留已经发布的旧 beta 记录。是否改变 fork 的未来说明策略单列决定，不能通过自动合入 `docs/release.md` 默改。

### D3 CI：保留手动触发，吸收打包修复

**本地意图：**控制自动化成本。**上游意图：**相关 PR/main push 必须证明真实打包资源。

**建议：**保留 `workflow_dispatch`；保留上游 asar 外内置资源、构建步骤与 packaged smoke。与 Nix、现有 workflow contract test 保持一致。不要把 `push/pull_request` 恢复作为此次合并副作用。

这项不存在绝对更优实现：自动打包提供更早的 artifact 证据，手动触发符合 fork 已确认成本策略。建议优先本地触发策略，因为这不是发布/CI 政策变更任务；新插件资源证据在实际发包前仍需做。

### D4 Web stream：两条改动都保留

**本地意图：**查找折叠 Activity 成员时，将原消息映射到 host 行。**上游意图：**通过 `rowVirtualizerRef` 维持虚拟化测量与状态连续性。

**建议：**保留 `props.messageHostIds` 的 memo 依赖，同时保留上游紧随其后的 `rowVirtualizerRef`。上游新布局作为主结构，本地 host 映射继续接入查找、跳转与 message-id 分配。仅选本地会缺 ref；仅选上游会把 Activity host 映射的依赖漏掉。

双方根因不同，无法用“哪侧更好”取代组合。上游对普通行虚拟化更完整，本地对折叠成员身份不可替代。

### D5 Selection E2E：恢复两个完整测试

**本地意图：**切换离开/返回聊天都清除 selection actions。**上游意图：**复制穿过图片保留 alt/source，只选图片时输出图片 Markdown，从图片下方开始时不带入图片。

**建议：**分别保留两个 `test()` 的完整 setup、正文和 cleanup。不要按两个标记各挑一侧：Git 已将相同的 `try`、路由和 finally 片段拼到不同测试的上下文中。顺序可沿上游测试文件结构，追加/安置本地切换回归，复用已有 helpers。

产品层保留本地工具栏生命周期和上游 rich clipboard 转换。需要同时测试 Ask/新窗口/preset 与 Copy，不能把 rich Markdown 无条件塞进继续提问动作。

### D6 法语：上游语言质量 + 本地功能 key + Reforged 产品身份

**本地意图：**覆盖 retry、runtime 回收和 fork 品牌。**上游意图：**修上下文、术语、空格、排版和英语残留。

**建议：**已有共同 key 优先上游法语句式，再按每个 key 的真实主语使用 `Paseo Reforged`；保留本地新增 key 并匹配新的法语术语/排版。用户可见产品名称与实际 CLI 命令、插件 ID、协议名、官方文档引用分开，禁止全文件替换所有 `Paseo` 字面量。

共同的“界面应可读且正确”目标，上游实现明显更好：本地存在 `QuitterPaseo`、`Paseo Reforgeddémarrer`、`Daemoncontinue` 和英语 registration/update 文案。但上游删除/缺少本地回收和 retry key 不能接受。25 块逐项决策见第 6.4 节。

### D7 Claude 模型：保留上游完整增量，去重 Sonnet

**本地意图：**已集成 Sonnet 5.5，按 `2.1.284` 门控。**上游意图：**在现有目录上再加入 Haiku 5.5，按 `2.1.293` 门控，默认模型不改。

**建议：**普通 catalog fixture 采用 `2.1.293`，保留 Sonnet 的旧/新版本边界测试，保留 Haiku 的边界、1M context、medium 默认、Off/effort、ID 规范化和 fast 不支持测试。CLI 当前目录存在性断言采用上游 Haiku；Sonnet 合同由其现有 catalog 测试保留，不为每个曾经新增的模型重复扩展真实 CLI 用例。

`12cd5345d` 与 `434060709` 的 Sonnet patch 等价，没有哪侧算法更优。上游当前目录与测试是超集，作为最终结构更好；不能把 fixture 退回旧版本后强加 Haiku 断言。

### D8 SDK 类型：导入取并集，定义采用 protocol 的单一来源

**本地意图：**支持 `AgentMessagePhase` 与 Activity。**上游意图：**把 feature toggle/select 类型统一到 protocol，增加速度控件元数据。

**建议：**同时导入 `AgentMessagePhase`、`AgentFeature`、`AgentFeatureSelect`、`AgentFeatureToggle`，沿上游 re-export。不要恢复已被删除的本地重复 feature interface。这是 import 并列插入，不是两套互斥数据模型。

### D9 Registry：采用上游模型传递与 options 职责

**本地意图：**自定义 provider 的身份、native archive、history、工具与 runtime 生命周期正确透传。**上游意图：**配置中显式声明的 ACP 模型必须真的应用；所有 provider 默认 options 统一在启动/恢复时合并。

**建议：**保留 `configuredModelIds` 的上游声明；其引用已经自动进入 `createSession` 和 `resumeSession`。同时保留完整 `ForwardedAgentSession`，包括 `initialTimeline`、`usageSession`、steer、archive 等能力。不要恢复 AgentManager 的旧 options validation，与新 registry 各合并一次。

对“配置与运行一致”的共同目标，上游实现更完整：覆盖没有 advertised models 的 ACP、resume、defaults 与 per-agent overrides；本地既有透传能力作为约束保留。不是把本地空块解释成“不允许配置未广告模型”。

### D10 Codex/OpenCode Usage 测试：保留意图，迁移到现职责

**本地意图：**Usage 跟随 provider 的 `CODEX_HOME`、活动 OpenCode model 与账号，不误用 custom base URL；Codex 当前回合 retry 隔离。**上游意图：**adapter 只提供 session identity/environment，插件负责账号发现。

### D12 Usage wire：给 fork 已发布协议留兼容边界

**本地意图：**当前 beta 客户端/daemon 可交错升级。**上游意图：**删除其认为未发布的 resolver，采用流式 Usage 和结构化错误。

**建议：**保留旧请求/响应的可解析合同及限期 `COMPAT` adapter，把上游流式 Usage 放入独立的新 namespace/能力位，例如 `usage.reports.list.request/response/update` 与可选 `usageReportStreams`。新 UI 在一次 capability 判断后使用新合同；既有旧 Usage 客户端在 client 边界归一化，旧 daemon 继续接受已有请求。旧 resolver 的账号归属意图由新 source/session 模型计算，不能另建一套抓凭证服务。

## 7. 无文本标记的意图、交互冲突与保留合同

“已确认”表示源码或纯合同检查已证明组合问题；“待验”表示组合路径存在、尚无运行失败证据。以下不把上游独有的新功能一概称为冲突。

### I01 内置插件版本拒绝：已确认

**本地意图：**保留 beta 身份。**上游意图：**Codex Usage/Muse 依赖 0.11 API。

冲突路径：D1 → `plugins/*/paseo-plugin.json` → `PluginRuntime.startBuiltinPlugin()` → `assertPluginCompatibility()`。同 npm semver 的稳定核心检查下，`0.10.0-beta.3` 对两个 `>=0.11.0` 均 false，候选 `0.11.1-beta.1` 为 true；Antigravity 的 `>=0.10.0` 对两者均 true。packaged smoke 新增“每个内置插件启动”断言，会暴露该问题。

建议按 D1。验收要使用最终实际版本，检查全部 builtin catalog/provider 注册，不能只测 fixture 中 `>=0.9.2` 的一个插件。

### I02 Usage 新旧 wire 双向不解析：已确认

**本地意图：**已纳入 beta 的 batch report/resolver 保持兼容。**上游意图：**以流式和 session-based discovery 替换未发布接口。
