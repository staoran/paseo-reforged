## 1. 目标与完成契约

- 当前理解：0036/0053 的编辑与原文重新生成功能在同一 daemon 进程内可用，但重新打开软件并触发 daemon 冷启动后，最后一条纯文本用户消息仍在，`replayKind="text_only"` 资格证明却丢失，所以 App 不显示编辑入口。
- 核心目标：只持久化最新纯文本用户消息的精确编辑资格证明，使受支持 provider 的同一 Paseo agent、同一原生 session/thread 在 daemon 重启后仍可编辑最后消息；不得用文本、位置或 provider 历史猜测资格。
- Done Contract：
  - live canonical 用户消息具有 `replayKind="text_only"` 和稳定 `messageId` 时，Agent 存储记录同步保存可选的 `lastReplayableUserMessageId`；最新用户消息不可重放或 provider persistence identity 改变时清除该字段。
  - 使用同一 `PASEO_HOME` 重启 daemon 后，首次按需恢复 Agent 与 provider history 时，只给原生 `messageId` 完全匹配该持久化证明的用户消息恢复 `replayKind="text_only"`。
  - 恢复后 `agentId`、`workspaceId`、provider、`sessionId` 和 `nativeHandle` 均不变，不创建新的 Paseo session、provider session/thread、workspace 或隐藏副本。
  - provider history 中找不到该 ID、匹配项不是最新 canonical 用户消息、记录缺少证明或 persistence identity 已变化时，保持不可编辑并清除陈旧证明；绝不按文本相同、最后位置或 provider 类型补猜。
  - 旧存储记录无新字段时继续合法加载且不显示入口；图片、附件、结构化输入及不支持 0036 原位编辑能力的 provider 不获得资格。
  - 不依赖或提前实现 0042 的全量持久化 Timeline；不改变 0036/0053 的 RPC、capability、same-session 回退与原文重提语义，不新增 App feature gate 或 UI 入口。
  - 公共 daemon restart E2E 精确覆盖冷启动症状并 RED -> GREEN；既有 App model 与 Playwright 合同继续证明恢复 marker 后入口可用；受影响测试、typecheck、lint、format 与 diff 检查通过。

## 2. 范围与事实

- 范围内：
  - Agent 内部存储 schema 增加向后兼容的可选编辑资格证明。
  - live timeline 事件对最新资格的设置/清除、snapshot 持久化、存储恢复与 provider history 精确复原。
  - provider persistence identity 变化、历史不匹配、非纯文本最新消息和 legacy 记录的 fail-closed 行为。
  - 公共 WebSocket / `DaemonClient` 跨两个真实 daemon context 的定向回归，以及既有 App model/UI 合同回归。
- 范围外：
  - 0042 的 durable Timeline、epoch/row/index 全量持久化或 `bootstrap.ts` 接入 `durableTimelineStore`。
  - 为 daemon 升级前已经存在且没有资格证明的旧消息回填入口。
  - 根据 provider history、文本相等、消息顺序或 provider 能力推断纯文本可重放性。
  - 编辑任意历史消息、附件或 assistant 消息，以及支持新的 provider。
  - 修改现有“回退到此消息”功能、创建/复制 session/thread 或回滚工作区文件。
- 当前任务单元：修复“已由 live 路径证明 eligible 的最后消息在 daemon 冷启动后丢失编辑入口”这一条持久化纵向链路。
- 轻量评估：`升级 standard`；根因和边界明确，但修改跨 Agent 存储、恢复、timeline hydration 与公共 daemon E2E，存在 legacy 与陈旧证明风险。
- 已确认事实：
  - 自动反馈环使用新的 `AgentManager + AgentStorage` 连续复现：`liveReplayKind="text_only"`、`coldReplayKind=null`、`coldLifecycle="idle"`、`editTriggerEligible=false`。
  - 仅 `closeAgent()` 不能模拟缺陷，因为同一 `AgentManager` 仍保留内存 timeline；必须建立第二个 daemon/manager context。
  - 生产 `bootstrap.ts` 给 `AgentManager` 接入了 `AgentStorage`，但没有 durable timeline store；`AgentStorage` 当前不保存 `replayKind` 或对应资格证明。
  - `normalizeReplayableTimelineEvent()` 只标记非 history 的 canonical App 纯文本提交；provider history hydration 按设计不猜测 `replayKind`。
  - Codex、Pi、OMP 的 live/history mapper 都保留稳定原生 `messageId`，可作为精确关联键；0036 已限制原位编辑只支持这三个 provider。
  - 已安装 daemon 的 feature gate 与 provider capability 均正常；冷启动旧 idle 会话缺 marker，而本次 daemon 启动后发送过消息的 idle 会话有 marker。
  - 0053 只取消“replacement 文本必须变化”的门禁，不能修复入口资格丢失。
- `grilling` 结论（如使用）：`N/A`；症状、根因、legacy 策略与 same-session 身份边界均已明确。
- 风险与未知：Agent snapshot 异步写入必须保证 marker 与 persistence identity 不发生旧写覆盖；强制 hydrate、rewind 失败及 provider thread/session 变化时不得残留错误资格。真实 Codex/Pi/OMP 冷启动 smoke 依赖本地安装和会话，自动测试先使用保留原生 history 的 mock provider 锁定公共行为。
