## 1. 目标与完成契约

- 当前理解：运行时上下文中的工具调用标题、摘要仍使用 Interface 字体 token，普通工具调用也没有消费“默认展开推理详情”；该设置目前只影响 `thinking` 工具项。
- 核心目标：工具调用标题和摘要跟随“设置 -> 外观 -> 工作区字体、字号”；`thinking` 与普通工具调用的详情初始状态都跟随 `autoExpandReasoning`，同时保持 Activity Fold、移动端详情面板和用户手动开合语义不变。
- Done Contract：普通工具和 `thinking` 都接收一致的 `defaultExpanded`；只有 `thinking` 继续接收 `forceInline`；工具 badge 的标题、摘要及加载镜像文字使用 workspace 字体族、`workspaceFontSize.base` 和相应行高，Web 文本带 workspace surface 标记；定向单元测试、typecheck、lint、格式与差异检查通过；不新增或运行 e2e。

## 2. 范围与事实

- 范围内：`packages/app` 的工具调用默认展开 props 投影、工具 badge 标题与摘要 typography、对应纯单元测试。
- 范围外：父级 Activity Fold 的运行中/完成后折叠规则、`toolCallDetailLevel` 的摘要/完整数据投影、移动端详情面板模式、代码与命令输出字体、Playwright/e2e、daemon、提交与发布。
- 当前任务单元：设置到 `ToolCall` props 的默认展开契约与 badge typography token 契约均已完成 Red/Green，并通过定向回归和静态检查。
- 轻量评估：`standard`；改动边界局限于 App 展示层，但跨设置投影和共享 badge 样式，需两个独立单元 seam 与静态回归。
- 已确认事实：`AgentStreamView` 已读取 `autoExpandReasoning`，当前只向 `toolName="thinking"` 传递 `defaultExpanded` 和 `forceInline`；普通 agent/client 工具均未传递。`ToolCall` 用 `useState(defaultExpanded ?? false)` 保存初始状态，用户后续手动切换不会被默认值持续覆盖。`ExpandableBadge` 的 `label`、`secondaryLabel`、`shimmerText` 当前使用 `theme.fontSize.base`，且标题/摘要文本没有 `WORKSPACE_SURFACE_DATASET`。
- `diagnosing-bugs` 结论：设置项存储和设置 UI 均有效，影响面缺口位于 `AgentStreamView` 的普通工具 props 投影；字体缺口位于共享 badge 的文本样式与 Web workspace surface 标记。`autoExpandActivity` 与 `autoExpandReasoning` 是两条独立状态链，不应合并。
- 风险与未知：`ExpandableBadge` 还承载 activity、todo 和 overview group；统一使用 workspace typography 与上下文区域的现有字体合同一致，详情代码字体保持不变。设置切换对已挂载项沿用既有 keyed remount 语义；无可打开详情的工具会被排除在有效展开状态外，避免错误禁用父级滚动。
