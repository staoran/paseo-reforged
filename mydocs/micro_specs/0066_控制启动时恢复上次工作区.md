## 1. 目标与完成契约

- 当前理解：iOS、Android 与 Electron 冷启动时默认进入全局项目选择页，不再自动恢复退出前的 workspace；用户可在常规设置中重新启用恢复
- 核心目标：用一个按设备持久化的开关控制已安装客户端的冷启动 workspace 恢复，同时不改变浏览器和会话内导航
- Done Contract：默认关闭时，有已保存 host 与 workspace 的移动端/Electron 冷启动落到 `/open-project`；开关开启时继续经 `/h/[serverId]` 恢复 workspace；浏览器、深链接、通知目标以及会话内主机根路由行为不变；设置可持久化并通过自动化验证

## 2. 范围与事实

- 范围内：App settings 新增布尔项 `restoreLastWorkspaceOnLaunch`，默认 `false`；General 设置页在移动端和 Electron 显示开关；根 `/` 的冷启动策略读取该设置
- 范围外：不删除或清空 `paseo:last-workspace-route-selection`；不修改 workspace 记忆规则；不改变 Web 浏览器启动恢复；不改变 `buildHostRootRoute()` 的会话内、深链接、通知和错误恢复调用方
- 当前任务单元：共享 Expo App 的设置持久化、冷启动路由决策、设置 UI、翻译与路由文档
- 轻量评估：`standard`；跨设置、路由、UI、翻译和测试，但公共边界清楚且不涉及协议、数据迁移或跨项目改动
- 已确认事实：`resolveStartupRoute()` 是根 `/` 的纯启动策略 seam；`resolveHostIndexRoute()` 还服务多个非冷启动主机根路由，不能全局关闭其恢复；全局 `/open-project` 自带 `HostRouteBootstrapBoundary`；现有 App settings 会为旧存储补齐默认值
- `grilling` 结论（如使用）：未使用；默认关闭与用户“不要自动打开”的要求一致
- 风险与未知：必须等待设置完成 hydration 后再决定路由，避免已开启用户被默认值抢先重定向；真实 iOS/Android 与 Electron 冷启动仍需手工冒烟确认
