## 1. 分类与比较标准

| 分类           | 判定依据                                                    | 处理原则                                             |
| -------------- | ----------------------------------------------------------- | ---------------------------------------------------- |
| 同源修复冲突   | 同一原始修复经 cherry-pick、等价 patch 或可追溯移植进入双方 | 去重，再检查移植时的上下文差异                       |
| 同缺陷独立修复 | 修复同一问题，但没有同源 patch 证据                         | 比较触发条件、覆盖范围、状态所有权与失败路径         |
| 同目标演进     | 用户目标接近，实现边界或架构不同                            | 选更完整的职责划分，吸收另一侧有效细节，避免双重权威 |
| 并行改动       | 独立能力或测试插入同一位置                                  | 分别保留，重建正确结构                               |
| 真实意图冲突   | 可观察行为、交互、迁移或仓库政策不同，原样不能同时成立      | 明确取舍与损失，待确认后实施                         |
| 派生物冲突     | 版本、lockfile、依赖哈希由上层输入决定                      | 先定输入再生成，不能任选一边                         |

`git log --cherry-mark --left-right --no-merges HEAD...目标` 未发现 `=` 等价项。结合已查提交及 PR，**本轮没有确认到严格意义的同源重复修复**。这不证明绝无历史移植，但不足以把任何块按“同一补丁已存在”删除。上游 CI 提交正文带有其自身的 cherry-pick 来源，也不代表本地包含那个来源。

几个容易混淆的结论：

| 主题                       | 分类                         | 哪方实现更好                                                                            |
| -------------------------- | ---------------------------- | --------------------------------------------------------------------------------------- |
| Activity 与整轮折叠        | 真实意图冲突，叠加架构演进   | 上游虚拟化、阅读锚点和统一展开状态更好；本地显式 final 边界、安全可见项和时长语义更完整 |
| 晚到事件的 turnId 归属     | 同缺陷独立修复 / 同目标演进  | 上游按本次实际修改的 row 归属更通用；本地 phase 和跨历史尾部补全仍需保留                |

## 2. 双方总体意图

### 2.1 本地 Reforged

本地保留 Reforged 的包身份、应用 ID、更新源及每个已发布 beta 的历史。自动 CI 以较窄检查为主，八分片 browser E2E 和桌面打包按既有手动政策运行。上一轮曾把 Android module tests 纳入 app CI；本次上游撤回它，属于需要重新评估的检查成本取舍。

聊天使用已确认的 [F07 合同](0121_F07_Activity整轮过程折叠.md)：只对有可靠 phase 的 Codex 消息折叠过程，以显式 `final_answer` 为边界；旧历史不猜测 final。运行中过程强制展开，没有 final 的失败或取消不折叠。错误、plugin、运行中的工具和待回答的 `request_user_input` / `request_user_input_async` 保持可见。“已处理 + 时长”、独立的 `autoExpandActivity`、view 内手动状态都属于现有交互。

Workspace 与 Agent 合同包括：Ready 不随已读改成 Done；普通已读 Ready 参加七条折叠，运行、等待、失败及未读 Ready 常显。关闭标签有 pending、失败和重试；History 恢复优先复用缓存，provider 恢复与 timeline 同步完成前不开放 composer / archive。daemon shutdown 保留历史驻留信息，显式关闭才记为 closed。手动关闭闲置 runtime 不唤醒 stored-only Agent，不等同于归档。

最近提交 `f1a545b138` 不是可丢弃的旧恢复路径：它要求先发布 restore 状态，再打开缓存对话；provider 历史一次安装后发 timeline replacement，避免把旧消息当 live 重播而清空或重排当前视图。Windows Terminal、WindowsApps alias、Windows 文件路径解析、选中文本提问与保存 preset 同样是需保留的本地能力。

### 2.2 上游 Paseo 0.14.0

上游把长对话阅读统一成三种 `chatDisplay`：Full、Collapse tool calls、Collapse turns。整轮以真实 run / trigger 组织，完成后保留最后一条 assistant message，其他过程折叠；展开内容仍是虚拟化列表的真实行，搜索、outline 和阅读位置共享同一映射。新安装默认 Collapse turns；原上游用户按旧工具详情设置迁移。

历史读取、缓存尾部和本地挂载沿完整可用轮次截取，40 是软目标，长轮次没有内部条数上限。后续修复继续调整 late lifecycle 归属、旧 host 协商和 thinking 可见性；目标 SHA 的行为优先于早期 PR 中间版本的描述。

上游新增一小时闲置自动释放 runtime，每分钟扫描，默认开启，可在 host 设置中实时关闭；保护 daemon 跟踪的工作、后代、权限、队列和 finish notification 意图，允许 provider 额外否决。它保留 Agent 记录和会话，下次 prompt 恢复原 session，不执行归档。

移动端让子 Agent 在原列表 Sheet 内打开，支持返回列表和父 Agent；内嵌 Sheet 不一定在 `sheetsByWorkspace` 中。桌面新增按 host / project 记住 editor 和 Xcode 探测；CI 删除阻塞普通检查的 Android prebuild / module tests，并通过根依赖 hoist 清理重复 Expo SDK。

**方案 A，推荐的行为基准。** 保留 F07 的 phase 边界、可见例外、时长和现有默认意图，复用上游单一 row/host、虚拟化和工具展开结构。工作量大于选一边，主要成本在模型、设置迁移与搜索锚点的配套改造。它不保证只改冲突块就能完成。D03 确认前，不预定所有旧设置都能无损装入三种新模式。

**方案 B，上游完整交互。** 使用上游三模式、run 边界和默认迁移，移除独立 Activity 语义。实现和长期跟随上游的成本较低，但会失去显式 final 分段、部分重要行常显、时长和独立默认开合；需要用户明确接受这些变化，随后同步 F07 的合同，而不能保留一份已失真的旧规格。

上游迁移规则不能原样照搬：本地旧 `toolCallDetailLevel=detailed + autoExpandActivity=false` 已经折叠完成的 Codex 过程，迁成 `full` 会让它全部展开；`overview + autoExpandActivity` 同时表达工具组和 Activity 默认，单个枚举未必完整容纳。必须列出四种组合、无旧字段、新安装、旧历史无 phase 的结果，再决定是否保留一个已有独立偏好。不得用丢字段掩盖迁移损失，也不得运行 `presentation.turns` 后再套 `projectActivityLane`。

| 操作                     | 本地现有意图                                                                  | 上游新增意图                                                 | 合并约束                                                                  |
| ------------------------ | ----------------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------- |
