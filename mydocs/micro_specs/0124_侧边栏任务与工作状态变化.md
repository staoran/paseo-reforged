## 1. 目标与完成契约

- 当前理解：用户已确认“任务状态变化”指 Workspace 的 `Working / Ready to review / Done` 分组，连同现有 `Needs input / Failed` 优先级；`Ready to review` 包含仍为 `idle` 的 Agent，无论结果是否已读；Agent 的 todo 清单进度不在本项范围
- 核心目标：定义 Workspace 状态事实源与可见转换，不把 `idle`、未读和 Agent runtime 驻留混成一个布尔值
- Done Contract：实现 Workspace 分组真值表、独立未读视觉与读状态菜单，并保持 `statusEnteredAt` 的同桶保留、换桶更新时间语义

## 3. 实施落点

- `packages/protocol/src/agent-state-bucket.ts` 将已读 `idle` 归入 `attention`，已读 `closed` 仍为 `done`；权限、失败和运行优先级保持不变
- `packages/server/src/server/workspace-directory.ts` 只用实际参与分桶的 Agent 计算 `statusEnteredAt`；同 Workspace 子 Agent 的非运行状态不参与 Workspace 分桶和进入时间
- `packages/app/src/utils/workspace-agent-activity.ts` 保留最近根 Agent 的状态补足，同时汇总所有未归档根 Agent 的未读事实；读状态菜单依据独立 attention 和服务端的可标未读条件判断
- `packages/app/src/hooks/sidebar-workspaces-view-model.ts` 将未读事实交给侧边栏行；`sidebar-status-list.tsx` 只在状态组对未读 Ready 显示 `600` 标题和绿点，已读 Ready 维持普通视觉

## 4. 已确认状态矩阵

| 输入事实                                          | 分组结果          | 未读视觉                                 |
| ------------------------------------------------- | ----------------- | ---------------------------------------- |
| 有正在运行的 Agent turn 或 Workspace 终端运行贡献 | `Working`         | 按现有运行态样式                         |
| 有权限请求                                        | `Needs input`     | 按现有权限样式                           |
| 有失败状态                                        | `Failed`          | 按现有失败样式                           |
| 无更高优先级，至少一个根 Agent 为 `idle`          | `Ready to review` | `requiresAttention` 时标题加粗并显示绿点 |
| 无更高优先级且无 `idle`，但存在未读完成 attention | `Ready to review` | 标题加粗并显示绿点                       |
| 无上述状态，Agent 为 `closed` 且已读              | `Done`            | 普通样式                                 |
| 无上述状态，Agent 为 `initializing` 且已读        | `Done`            | 普通样式                                 |
| 无 Agent，终端也无活动或未读贡献                  | `Done`            | 普通样式                                 |

优先级固定为 `Needs input > Failed > Working > Ready to review > Done`。`Ready to review` 的归类由
Agent 是否仍为 `idle` 或是否存在未读 attention 决定；未读只决定 Ready 行的强调，不决定 idle 是否属于 Ready。
同 Workspace 子 Agent 的非运行状态仍留在 subagents track，不把它们的 idle 或未读提升为 Workspace Ready。
分组展示顺序保持 `Needs input / Failed / Ready to review / Working / Done`；聚合优先级与展示顺序各沿用现状。
本地创建中的临时 Working 覆盖和加载图标沿用现有逻辑；`initializing` 本身不作为正在执行 turn 的事实。

## 5. 决策与验收

1. 已确认：已读 `idle` 仍属于 `Ready to review`；只有没有更高优先级贡献、没有 `idle` 且没有未读贡献时才进入 `Done`
2. 已确认：恢复旧 `0083` 的状态组未读强调；未读 Ready 使用 `600` 标题和绿点，已读 idle Ready 使用普通字重并撤销绿点。项目分组和 Pinned 行沿用现有视觉
3. 已确认：保持 daemon 的多来源优先级 `Needs input > Failed > Working > Ready > Done`；客户端在 daemon 报 Done 时的最近根 Agent 补足继续沿用现有逻辑，并在实施时覆盖竞态
4. 已确认：保持现有 `statusEnteredAt` 算法。同一分组内读/未读变化不更新时间；分组变化时沿用现有逻辑更新时间，不新增完成时间或阅读时间字段
5. 已确认：读状态菜单依据真实 attention 和现有服务端可标未读条件判断。已读 idle Ready 可标为未读；未读 Ready 可标为已读；保留权限和失败的现有处理
6. 实施验收：定向测试覆盖运行、idle 已读/未读、closed 已读/未读、同/跨 Workspace 子 Agent、多根 Agent 和读状态菜单。Ready 内读/未读变化保留时间，重新运行或关闭最后一个 idle 后换桶更新时间；新增浏览器用例验证读/未读切换的绿点和字重
