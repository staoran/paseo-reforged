## 2. 本地 Reforged 的意图

### L1 普通标签关闭是完整的资源生命周期操作

`a0df644e1` 改变了旧 0128 中“根标签归档、子标签只关布局”的合同：现在所有 managed Agent 的普通标签关闭都归档并结束 runtime，不再为运行中 Agent 弹确认。关闭失败保留标签、展示原因并可重试；只有 teardown 成功才写关闭历史和移除视图。provider 自有子会话仍没有独立 managed runtime。

关闭历史按 workspace ID 隔离，本地最多保留 100 条；保存 tab ID、标题、目标和视图状态。恢复 managed Agent 要回到同一个 Agent/provider 会话，终端则新建 shell，不能重跑旧命令。文件未保存确认、终端停止确认继续存在。关闭最后一个内容标签进入 **New workspace**，Explorer 工具标签不算剩余内容。

未推送的 HEAD `0b936e4d6` 又修复了慢恢复：先显示恢复面板，再等待 resume；终端先写缓存，避免目录 reconcile 抢先删掉刚恢复的视图。因此以 `origin/main` 代替 HEAD 分析会漏掉本地最新行为。

### L2 阅读与原始消息身份保持稳定

0121/F07 的 Activity 折叠是展示投影：Codex 出现显式 `final_answer` 后，前面的过程折叠成稳定 host；失败或取消但没有 final 时不能伪装成完成。原消息保留，搜索、Outline、跳转、复制仍能找到它们。迟到 phase、canonical cursor、跨 turn 顺序和 retained panel 切换都属于这个合同。

F11/F12 让 assistant 选区可继续提问、开新窗口、保存 preset；`28937ae61` 清理非活动会话的旧选区，避免把上一会话文字写到当前输入框。本地这些操作并不依赖旧 Markdown 分块方式。

### L3 中文 Markdown 与 Windows 文件定位不能回退

0126/F20 有两个独立目标：strong 显示为 700；assistant 正文容忍 `**句末标点。**紧接文字`，同时保护嵌套、转义、inline code、fence code。旧 parser 还负责未闭合强调、链接和图片的流式视觉稳定。这些测试含用户原始复现文本，不能用“换了引擎”直接删掉验收目标。

0123/F24 保留 Windows 中文/空格/编码链接、`/C:/…` 形态、工具卡提供的行号及 `file:///…:1`。目标是打开真实文件并跳到正确行，不能只证明字符串解析成功。

### L4 工作状态、未读、runtime、消息时间分别建模

0124/0125 让闲态已读 workspace 继续处于 Ready，attention 只表示未读或待处理；`runtimeAttached` 表示 daemon 是否持有 provider runtime，不由 Running/Ready 推断。驻留详情经 `95563980b` 移到 workspace hover card，目录未同步或连接离线时不能展示伪权威进程数量。

`c1e22bf5e`、`0fdb2c68a` 的侧栏时间来自最新用户/assistant 消息，durable/replay/resume 后仍保留；读操作、标题、纯工具事件或关闭/恢复会话不能把旧聊天刷新成“刚刚”。

### L5 新建与导入的标题服从当前用户语境

F05 以导入列表中用户看到的会话名称命名新 workspace 和 Agent；F06 让新建名称遵守当前 App 语言。`875c7e650` 可配置启动时恢复上次 workspace 或进入 New workspace，但不覆盖显式 deep link。这些是独立功能，不能因新建页重构回到固定英文标题或无条件跳首页。

### L6 fork 的发布和兼容合同继续有效

Reforged 有独立的名称、安装 ID、更新仓库、签名、beta 历史和 What's new 输入。内部 `@getpaseo/*` 包名保持兼容。`507e66ffb` 关闭自动浏览器 E2E、桌面打包和 Nix 检查，保留手动运行，这是成本政策。

0128 已保留发布过的 `usage.list_reports.*` batch、`agent.resolve_usage_report.*` resolver，新增 stream 使用 `usage.reports.list.*` 和 `features.usageReportStreams`；兼容代码有到期条件。新功能不能借“上游原来未发布”这一前提删除 fork 已经发布的合同。

## 3. 上游的意图

### R1 三端使用同一 Markdown 引擎和完整消息宿主

`eb1a8a2ec/#6973` 使用 `react-native-enriched-markdown`/MD4C，完成态一条 assistant 消息只占一行。原生文本选择可以跨段落、标题和列表，引用定义在完整消息作用域内解析；代码复制、表格滚动也由新的 renderer 边界承担。

上游删除旧 Markdown 样式与 markdown-it 流式显示路径。原生流式更新只在 renderer 内分稳定 head/变化 tail，展示模型不再制造 `:block:N` 消息。markdown-it 仍服务富文本 clipboard，因此“parser 还存在”不代表界面仍用它。

### R2 手机使用可叠放、可关闭的预览 sheet

`e135e9c10/#6827`、`6ad124758/#6885`、`e5124b039/#6958` 让手机文件、managed 子 Agent、provider 子会话进入 sheet。sheet 用来查看，隐藏 composer；managed 子 Agent 可通过 **Open as tab** 回到普通交互面板，保持同一 tab ID 和状态。

sheet 由全局 primitive 管堆栈、父层、脏文件保护与可见区域；自身不持久化，reload 回到普通标签。大屏使用普通 split pane。上游普通 managed 根标签关闭仍归档、运行中确认，managed 子标签只改布局，和本地 L1 存在真实分歧。

### R3 路径解码遵守输入来源，目录仍是可打开目标

`563c014dc/#6520` 解决非 ASCII 文件链接，并明确 href 与原始 inline-code 路径不同。href 的 `%20` 可能代表空格，原始路径里的 `%20` 可能就是文件名；编码的行标记也不能提前变成真正的 fragment。后续目录链接改动把文件夹交给 Files，显式文件链接不再依赖扩展名白名单。

### R4 性能优化守住集合身份与完整目录

`0d7a234e6/#7157` 不只复用 workspace entry，还在成员和顺序未变时复用整个 collection，减少 retained sidebar 恢复时项目行重渲染。

`0009a7e71/#5039`、`c1558d29e/#7141` 的 background workspace 只是发现策略：默认列表隐藏，按 ID 打开和恢复仍可访问；canonical 目录必须完整，不能被过滤列表替换。App 在能力门控后复制两类对象，仅在侧栏过滤；旧缓存缺失 background 标志时要失效 workspace cursor。

### R5 保留失败前的有效 Usage 结果，修正命令送达

`cf62b0091/#7246` 在刷新失败时保留上次成功快照和成功时间，同时继续显示本次失败；不能把失败时间假装成 quota 的成功更新时间。

`cd77ecd83/#7169` 让来自其他 Agent 的 slash command 去掉 sender envelope 后到 provider，OMP 闲态 follow-up 真正起 run，忙时保留 streaming prompt 路径。这和本地资源关闭 fence 解决不同问题。

### R6 桌面首窗、CI 和官方发行继续演进

`9551b2cc1/#6726` 在 Linux 文档已经加载但 compositor 没有首帧时显示窗口，其他平台保留 ready-to-show 路径。它不等于故障后的 renderer 恢复。

`a5c566f80/#7275` 将 format/lint/SDK/relay 合并进 quality，拆 Windows server 测试、8 个 Playwright 分片、取消所有 ref 的过时 run；官方愿意维持自动 E2E。官方 beta/stable 的 EAS 与 TestFlight 分发也继续变化，但不能据此推断 Reforged 账号、组和凭证已经配置好。

## 4. 建议决策与取舍

以下是实施建议，不是已经合入的结果。D1–D12 中涉及产品政策的部分须由后续实施指令确认；本次分析不需要先选择它们才能交付。

### D1 普通标签与 sheet 的关闭必须有两份明确合同

**本地意图：**关闭普通标签就结束 managed runtime，根/子一致，不再多一次运行确认；恢复历史让这种关闭可逆。**上游意图：**sheet 是临时查看层，关闭收起；managed 子 Agent 可在父会话委派工作期间继续运行，普通子标签也仅关布局。

**冲突：**不能把 `target.kind === agent` 当成所有宿主都应归档的充分条件，也不能借 sheet 的 layout-only 分支把本地普通子标签退回只关视图。归档是 daemon 全局动作，收起 sheet 是客户端局部动作，别的客户端和父 Agent 都会受到前者影响。

**建议：**普通 managed 标签沿本地 L1；sheet 沿上游 R2，仅收起，不入关闭历史、不停 runtime；provider 子会话关闭仅改布局。批量关闭与 close-pane 使用同一普通标签合同，并保留未保存文件/终端确认。升级为普通标签后再关闭，才执行 managed 归档。当前预演已经有 sheet 直接 layout-close 的前置分支，应保留这一边界。

这使 fork 同时接受新预览宿主和已交付的关闭历史。若要让拖下 sheet 也停止子 Agent，是新增破坏性产品语义，应单独选择，不作为“修冲突”暗中实施。

### D2 关闭历史要恢复为原普通标签，错误必须在手机可见

**本地意图：**成功结束资源才入历史；恢复同一 managed Agent 和原视图状态；慢恢复先给可见面板。**上游意图：**compact 的 `intent: reveal` 可能优先进入 sheet，sheet 不算普通标签、不写持久化布局。

**冲突：**`getWorkspaceTabs()` 仅收集 `layout.root`，历史 capture/去重/最后内容判断都继承此边界。若恢复仍走通用 reveal，文件或子 Agent 可能被恢复成 sheet，already-open 查询却看不见它，导致重复 resume。关闭最后普通标签时仍有 sheet，导航 `/new` 又可能丢失预览上下文。桌面分支中的 `closeErrors` 在手机不渲染，失败标签虽然保留却没有原因和重试入口。

**建议：**history 只记录普通标签；恢复明确请求普通标签宿主，若目标已在 sheet，提升同一对象后恢复状态，而不是创建第二份。展示去重查普通标签与 sheet，生命周期去重按 managed Agent 身份执行；不要把所有 `getWorkspaceTabs` 调用一律扩大，批量普通标签关闭仍不能扫到预览层。恢复失败保留历史，成功才删历史。最后内容关闭前先按未保存保护处理 sheet，再执行本地 `/new` 合同。

错误提示放到 mobile/desktop 共享可见边界，并验证 sheet 遮盖下仍可达到 retry。保留 `0b936e4d6` 的提前显示和终端缓存顺序，不把等待慢 resume 的空白窗口带回来。

### D3 选区 Ask 必须先到可输入的宿主

**本地意图：**选中文字后立即放入当前 Agent draft；新窗口和保存 preset 继续工作。**上游意图：**sheet 用来查看，不显示 composer，避免手机双输入框/键盘冲突。

**冲突：**简单合并会保留 `handleSelectionAction`，但 `showsComposer === false`，Ask 只修改不可见 draft。用户重复点击可能重复追加文字，还以为操作失败。

**建议：**managed sheet 的 Ask 先复用 `openSheetAsTab` 提升同一 tab/状态，确认交互面板可用后写 draft并按现有焦点合同显示输入；不在 sheet 内再造 composer。新窗口继续按 compact 决定布局，preset 可直接保存。provider 子会话仍只读，不增加向其发送的能力。保留 inactive panel 选区清理和 fullscreen editing session 的作用域，避免对旧面板写入。

### D4 采用新 Markdown 架构，迁移行为而非复活旧分块

**本地意图：**700 字重、中文标点相邻 strong、流式不露星号、Activity phase/定位正确。**上游意图：**一条完整消息一个原生文本宿主，三端统一 renderer；旧 parser 仅服务 clipboard。

**建议架构：**采用上游一消息一行；删旧 `nativeBlocks` 及缓存，不恢复已删 `blockGroupId/blockIndex`。Activity 保持在原消息投影层，保留 turn/phase/cursor/time 和稳定 host；插件继续先拿原消息。上游更适合跨段选择和引用解析，本地块缓存不是必须保留的产品功能。

**F20 不能判定已被新引擎修好。** 新 `source.ts` 的 HTML/image/entity/spoiler/link 适配没有对应旧 punctuation 规则。完成态、流式、clipboard 是三条需分别验证的路径。先用真实 renderer 复现下列语料，若确实不支持，再在新 renderer/源适配边界做最小修复；不能给 markdown-it 留一个已无人调用的 UI 修复，也不能用全局替换 `**` 破坏源文本。

- 原始语料：`**外发员工预请款要单列一条线。**例如财务先给员工运营款 300 元，员工现场付承运方 220 元，再退回 80 元`
- 嵌套：`**A。**B**C**` 应保留现有嵌套合同，不强制把中间 marker 提前闭合
- 保护：转义星号、inline code、fence、链接 label；完成消息的未闭合标记仍与现有 completed 合同区分
- 流式：未闭合 strong 与半个结束标记、未完成链接/图片，在新引擎真实边界判断是否仍满足旧视觉承诺

700 字重转为新 renderer 的实际样式/输出断言。旧 `markdown-styles` 实现和对应 factory 测试接受删除，clipboard 仍需保留适用的完成态语义测试。新原生依赖必须重建二进制，不能只靠 JS/OTA 或旧 dev client 宣称迁移完成。

### D5 Activity、Find、Outline 和插件保留同一消息身份

**本地意图：**折叠后的原消息可以搜索，跳转先展开，再找到稳定 host。**上游意图：**区分 mounted history 与 live head，减少每个 delta 重算集合；插件行保留 source ID 与定位边界；history/live 使用统一 `StreamRow`，避免切段 remount。

**建议：**保留 `mountedHistoryMessageIds`、`mountedMessageIds` 与折叠可见集合各自职责，不能只是把 `visibleMessageIds` 重命名。Outline 按新接口接 mounted history，reveal 委托本地先展开；Find 使用可见性与源消息定位。history、live-head、虚拟历史三种外层 host 都保留本地 `data-message-id` 去重条件，并增加上游 `data-plugin-row`。

统一使用上游 `StreamRow`，把 Activity layout-item/host 映射纳入共同解析路径，删除旧 live 专用 renderer。保留 inactive 时清 Activity override 的 effect，但 `isActive` 只声明一次。迁移测试为一条多段消息仍保留 phase/cursor，不能保留“拆成两条”的断言或删除整个迟到 final 测试。

### D6 文件链接选择上游解码模型，保留本地定位入口

**本地意图：**Windows 编码路径可打开，工具卡跳行，`/C:/…` 与 `file:///…:1` 正确。**上游意图：**href 解码一次，raw path 原样保留；中文相对路径、字面 `%20`/编码行标记及文件夹都正确。

这是同缺陷独立修复，上游实现更完整：`decodeHref`/来源信息把“该不该解码”作为边界，本地 Windows 分支直接 `safeDecodeURIComponent` 会把真实 `%20` 文件名改成空格。建议采用 `parseWindowsFileLink` 与上游 inline opener，保留本地 `parseToolCallFilePath` 和工具调用行号，补入 slash-drive、file URL 尾缀测试。解析来源与 cache key 一起核对，不能第二层 resolver 再解码一次。

目录链接要继续进入 Files，而工具卡带行号的文件进入编辑器。两者共用 opener 时保留目标类型，不能把目录当文件或丢掉行号。组合验收用原始路径、href、工具 payload 三种入口。

### D7 侧栏采用上游 collection 复用，不丢本地状态字段

**本地意图：**驻留详情、目录可信度、消息时间准确，并复用未变化 entry。**上游意图：**retained sidebar 恢复时整个 collection 也应保持身份，成员/顺序变化仍可观测。

background 隐藏在侧栏投影层，不在 canonical 目录过滤。驻留计数继续使用已同步的权威 managed 目录，不把 background 隐藏当成 runtime 被释放，也不把 provider 子会话计为独立进程。

### D8 runtime 关闭 fence 与 Agent 间命令去包络按顺序并存

**本地意图：**idle runtime 正在关闭时禁止新命令越过 fence，避免关闭/重启竞争。**上游意图：**provider 能看见真正以 `/` 开头的命令，不被 sender envelope 遮住。

**建议顺序：**取得 Agent → 检查 `idleRuntimeCloseFences` 并保留拒绝行为 → 对字符串解析 sender envelope → 将内部命令文本或原 prompt 交给 `tryHandleOutOfBand`。非字符串/普通文本保持原样。不能把检查移到 provider handler 已产生副作用之后，也不能为保留 fence 回退上游 OMP follow-up 修复。这是两种独立约束，没有选边必要。

### D9 Desktop 两阶段恢复合并，不重启 daemon

**本地意图：**renderer 白屏或进程异常后，用户仍能从 native tray/dialog 恢复窗口；保留 Windows 更新后 GUI 启动修复。**上游意图：**Linux 窗口在已加载但未产首帧时不要永久隐藏。

**建议：**import 并集，首窗显示仍由 `showWindowWhenReady` 处理，故障/超时后由本地 recovery 状态机处理。核对 listener cleanup、窗口销毁、重复 reveal 和托盘生命周期；一个阶段成功不能把另一个阶段尚需的回调误清理。两者“看起来都是白屏”，根因和时点不同，不应互删。恢复动作不应引入重启 6767 daemon。

### D10 Usage 新快照自然扩展现有兼容边界

## 7. 无标记的代码、意图与交互冲突

这里是预演树或两侧新旧合同组合后的发现，不是又多算一批 Git 文本块。“已确认”指静态源码足以确定不相容，不表示已执行运行测试；“待验证”不能被写成已发生的线上故障。

### I01 手机关闭失败被新布局藏住 · 已确认 · D1/D2、C49

本地希望失败留标签并展示 retry；上游将手机内容移到单独分支。预演 `workspace-screen.tsx` L3857 开始的 mobile/desktop 分支，使 L3888 后的 Alert 只在 desktop 路径。直接保留冲突块会让手机用户关不掉标签却看不到原因。建议将错误反馈移到共享可见宿主，并保留原失败对象供重试，不能关闭失败后先移标签。

### I02 历史恢复可能被路由成 sheet · 静态路径已确认，交互待验证 · D2

本地 history helper 用通用 `intent: reveal`，上游 compact 会把文件和子 Agent reveal 到 sheet；`getWorkspaceTabs` 在预演 store L1638 只遍历 `layout.root`。already-open/close capture 也依赖它。建议恢复显式进入普通标签，已在 sheet 时提升原对象；已有 sheet 的查询和普通标签批量操作分开，防止重复 resume、重复视图和历史项消失。

### I03 最后内容标签关闭与 sheet/新启动页互相覆盖 · 真实意图冲突 · D1/D2
