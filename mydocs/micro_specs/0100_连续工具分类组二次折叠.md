## 1. 目标与完成契约

- 当前理解：现有时间线会把相邻工具调用按读取、搜索、命令、编辑等类别分别折叠；当类别频繁交替时，两段文字之间仍会铺开大量分类折叠行。
- 核心目标：把同一非工具内容边界内连续出现的多个分类组再组合成一个外层折叠，同时保留分类组和具体工具调用的原始顺序与可展开能力。
- Done Contract：
  - 连续工具调用包含两个以上分类组时，顶层只显示一个合计摘要折叠；展开后按原顺序显示既有分类组，分类组仍可继续展开具体调用。
  - 连续工具调用只有一个分类组时保持现有单层交互，不增加重复标题。
  - assistant/user 文字、thought、todo、plan、`speak` 及其他非分组内容继续切断外层序列；普通时间线与已加载 Activity members 使用同一合同。
  - retained history 与 live head 边界上的连续工具序列保持首个调用 host、运行状态和更新稳定性。
  - 定向投影与展开测试、根 typecheck、lint、目标格式和差异检查通过；可执行时补一个隔离 Web 交互验证。

## 2. 范围与事实

- 范围内：`packages/app` 工具调用投影模型、外层/分类组视图接线、展开状态和定向测试。
- 范围外：协议、daemon、设置键或迁移、工具分类规则、Activity 整轮折叠、提交、发布及无关工作区改动。
- 当前任务单元：一个 App 展示层行为单元，复用 0075 已验证的分类与 host 投影。
- 轻量评估：`standard`；跨投影、共享 Web/Native 视图和历史 revision，但不改公共 wire contract 或持久数据。
- 已确认事实：0075 当前按相邻语义类型切组；顶层与 Activity members 都经 `projectToolCallDetailLevel()`；组展开状态由现有 `ToolCallGroupExpansionState` 管理。
- `grilling` 结论（如使用）：`N/A`。
- 风险与未知：新增嵌套开合需确保 Native 历史 row revision、运行中序列 host、滚动高度和现有 E2E helper 不失效。
