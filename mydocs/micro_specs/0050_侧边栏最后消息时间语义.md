## 1. 目标与完成契约

- 当前理解：侧边栏相对时间必须以 workspace 中未归档根 Agent 的最后一条 `user_message` 或 `assistant_message` 的权威时间为基准，不因读取会话、恢复 Provider Runtime、工具/推理/usage 事件、状态切换或配置更新而推进。
- 核心目标：建立独立于 `Agent.updatedAt` 的 `lastMessageAt` 事实，贯穿持久化、wire snapshot、App Agent 模型和侧边栏 workspace 聚合，保持旧记录与旧 daemon 双向兼容。
- Done Contract：用户消息时间为 T1、助手消息时间为 T2、后续非消息活动或冷会话访问时间为 T3 时，侧边栏仍显示 T2；同一 workspace 多个根 Agent 取最大的有效消息时间；没有用户/助手消息时不伪造时间；协议兼容、定向 RED/GREEN、typecheck、lint 与差异检查通过。

## 2. 范围与事实

- 范围内：`lastMessageAt` 的 Agent 持久化字段、可选 WebSocket snapshot/list 字段、服务端消息时间推进规则、旧记录兼容、App 归一化与 replica cache、侧边栏 workspace 聚合及定向测试。
- 范围外：History/Command Center 等其他 `lastActivityAt` 排序语义、相对时间格式化算法、0048 Hermes 修复、0049 stored-only runtime 状态修复、0038-0046 性能计划、主 `6767` daemon、提交与发布。
- 当前任务单元：纠正 0034 侧边栏时间的数据语义，不改变其显示文案和刷新频率。
- 轻量评估：`切换 sdd-riper-one`；正确实现需要新增公共 wire 字段和持久数据字段，已越过 Light 的公共契约与数据边界。
- 已确认事实：App 当前在 `normalizeAgentSnapshot()` 中执行 `lastActivityAt: updatedAt`；侧边栏按 workspace 聚合未归档根 Agent 的最大 `lastActivityAt`；`AgentManager` 会为任意 live event 和冷会话恢复推进 `updatedAt`；现有 `lastUserMessageAt` 只记录用户消息；协议没有 Agent 级 `lastMessageAt`。
- `grilling` 结论：`N/A`；用户已明确消息范围为 `user_message` 或 `assistant_message`。
- 风险与未知：旧记录缺少助手消息时间时只能使用明确兼容策略，不能扫描或恢复每个 Provider Runtime；历史 replay、import、assistant 分片和系统生成的 `assistant_message` 必须按 canonical timeline timestamp 单调合并；新增字段必须 optional/nullable 且遵守 AOT schema 纯度；0050 执行时需增量合并 `agent-manager.ts`、`agent-storage.ts` 及 0048/0049 的并行改动。
