## 1. 目标与完成契约

- 当前理解：中文系统环境下，新会话首条消息生成标题时偶尔仍发送英文语言约束
- 核心目标：提交时使用同步解析出的应用 locale，所有应用内创建入口不丢失该语言，并拒绝明显不符合请求语言的标题结果
- Done Contract：异步 i18n 切换尚未完成时仍发送 `zh-CN`；直接 `create_agent_request` 与 Workspace Setup 的先建工作区请求均保留可选语言上下文且旧 payload 兼容；`zh-CN` 英文标题触发既有结构化重试，连续失败时不保留英文临时标题；定向回归、静态检查和格式检查通过

## 2. 范围与事实

- 范围内：I18nProvider 的解析 locale 暴露、新建工作区读取、create-agent 协议与 server 组装、本地化临时标题、对应回归测试
- 范围外：`paseo.json` 标题样式、既有标题重生成、完整的自然语言识别或强制翻译
- 当前任务单元：围绕同一创建链路的竞态和字段传递，保持公共字段可选
- 轻量评估：`standard`；涉及 app、protocol、client、server 四个 workspace，但不改变既有字段语义
- 已确认事实：`ensureI18nLanguageForRender` 调用 `changeLanguage` 为异步；New Workspace 当前读取可能过期的 `i18n.language`；`handleCreateAgentRequest` 只从顶层 prompt/attachments 重建 `FirstAgentContext`；Workspace Setup 先调用 `createPaseoWorktree` 或 `createWorkspace`，随后才创建 Agent，因此仅向后者传递语言不会触发工作区自动命名；所有结构化生成重试均失败时，既有实现会保留英文 prompt 作为临时标题
- 风险与未知：旧 daemon/client 的 wire 兼容；拉丁文字语言无法仅靠字符集精确区分，继续以强化提示词和 schema 描述约束；未调用真实 provider 做人工验收
