## 1. 目标与完成契约

- 当前理解：在当前会话空闲时，只允许编辑最新一条由 Paseo daemon 明确证明为纯文本的 canonical 用户消息；提交后在原 Paseo 会话和原 provider 原生 session/thread 内删除该用户 turn 及其回答，发送替代文本并重新生成回答。不得创建、复制、导入或导航到另一会话。
- 核心目标：以一个保持 Paseo 会话身份和 provider 原生会话身份不变、可兼容旧 daemon/client、不会隐式取消运行中 turn、不会回滚工作区文件的最小契约实现 Codex Desktop 类似的原位覆盖体验。
- Done Contract：
  - `server_info.features.*` 提供独立 daemon 兼容 gate，旧 daemon 下 App 不显示入口，也不发送新 RPC。
  - agent capability 新增独立的 `supportsInPlaceEditLastUserMessage`，不得用 `supportsRewindConversation` 推断原位编辑能力。
  - 首版只为 Codex、Pi、OMP 声明能力；Claude、OpenCode、Copilot ACP 和通用 ACP 保持不支持。
  - 只有最新 canonical 用户消息、agent 确认 idle、且 timeline item 带有 daemon 生成的纯文本可重放标记时才可进入和提交编辑。
  - 操作前后 `agentId`、`workspaceId`、当前 tab/route 和 provider persistence `sessionId/nativeHandle` 必须相同；只允许产生新的 replacement message/turn ID 和 timeline epoch。
  - daemon 在一个串行化操作中完成二次校验、原 session 内裁剪最后一轮、强制 timeline hydrate 和 replacement `startTurn`；编辑路径绝不调用自动 cancel、`thread/fork`、`forkSession`、agent/workspace 创建或 fork-context 流程。
  - 成功时替代消息只启动一次，旧回答从新 timeline epoch 消失；失败时保留草稿，并准确区分历史未变、历史已回退和历史状态未知。
  - 编辑操作只改变 provider 对话分支，不恢复、删除或暗示恢复原回答造成的本地文件改动。
  - App 提供最新消息气泡内联纯文本编辑、取消、提交 pending、防重复提交及可访问名称；非 eligible 消息没有编辑入口。
  - 协议、daemon 编排、三个 provider adapter、App 状态与 UI 的自动测试通过；真实 provider E2E 按可用环境给出证据或明确未验证原因。

## 2. 范围与事实

### 2.1 范围

- 范围内：
  - 新 daemon feature、agent capability、编辑 RPC、纯文本可重放标记及向后兼容解析。
  - Codex、Pi、OMP 的最新消息原 session 裁剪能力声明与契约测试。
  - daemon 侧 latest、canonical、idle、纯文本、非空变更、并发占用校验。
  - App 中最新用户消息的内联编辑、取消、提交及失败恢复。
  - replacement 使用新的 `replacementMessageId`，同一次 UI 重试复用该 ID，避免双击或响应丢失造成重复 optimistic/user message。
- 范围外：
  - 编辑任意历史用户消息、assistant 消息、synthetic/system 消息或 provider subagent 消息。
  - 图片、文件、mention、review、comment、结构化 content block、output schema 或其他附件的重放。
  - conversation + files 联合回退；本功能不会调用 `files` 或 `both` rewind。
  - Claude、OpenCode、Copilot ACP、通用 ACP 的适配；Claude 当前只能 fork 新 session，OpenCode 会同时恢复文件 snapshot。
  - 将本功能迁移到 `thread/fork.beforeTurnId`；fork 会创建新原生 thread，与本任务身份约束冲突。
  - 新增键盘快捷键、编辑任意轮次、完整 turn 参数持久化或附件编辑。
- 当前任务单元：完成“最新 + idle + 可证明纯文本”的一个纵向功能，不拆父子 Spec。
- 轻量评估：`升级 standard`。行为边界单一，但跨越公共协议、client、daemon、三个 provider adapter 和 App 状态，不能按 `fast` 处理；当前不改变数据库 schema、文件内容或权限模型，无需升级 Heavy。

### 2.2 与现有“回退到此消息”的硬边界

已确认：**现有“回退到此消息”与本功能不是同一能力，不能复用其产品语义或实现入口。** 当前用户消息上的 `RewindMenu` 调用 `agent.rewind.request`；虽然它不创建新的 Paseo agent，但 provider adapter 可能复制原生会话：

- Codex `revertCodexConversation()` 先调用 `thread/fork`，再在 forked thread 上 rollback，并把 `currentThreadId` 切到新 ID；源 thread 留在磁盘。
- Claude `forkSession()` 返回新 `sessionId`，Paseo 随后 rebind 到该新 session；首条消息回退还会启动 fresh session。
- assistant 回答上的“分叉消息”是另一套功能，会创建 draft 并导航到新标签页或新工作区；本任务也不得调用该链路。

本功能的原位身份不变量：

| 身份/状态                                     | 提交前后要求                                                 |
| --------------------------------------------- | ------------------------------------------------------------ |
| Paseo `agentId`                               | 必须相同，不创建或导入另一个 agent                           |
| `workspaceId` 与 tab/route                    | 必须相同，不新建标签页、draft 或工作区                       |
| provider persistence `sessionId/nativeHandle` | 必须相同，不 fork、fresh-start 或切换到复制的原生会话        |
| timeline                                      | 允许创建新 epoch；目标用户消息和旧回答必须从当前投影视图消失 |
| replacement                                   | 允许新的 client message ID、provider message ID 和 turn ID   |
| 工作区文件                                    | 保持当前磁盘状态，不执行文件 rewind                          |

用户已确认：这里的“不复制会话”不要求 provider 擦除同一 session 内不可见的树分支或审计历史；硬要求是不会产生另一个可恢复、可导入或可列出的 session/thread ID。若未来要求连同 session 内旧分支也物理删除，再作为范围变化重新评估 Pi/OMP。

### 2.3 该能力是否仅 Codex 支持

结论：**严格按原生 session/thread ID 不变，仍不是 Codex-only，但首版矩阵从四个缩为三个：Codex、Pi、OMP。Claude 当前只有 fork/fresh session 路径，因此必须移出首版。OMP 虽可支持，但不能使用 Paseo 当前的公开 `branch` RPC，必须走 same-session tree navigation。**

| Provider / CLI         | 已确认的原位语义                                                                                                                                                | 保持原生会话身份         | 首版决策 |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | -------- |
| Codex                  | 官方 Desktop 对当前 thread 执行 `thread/rollback(numTurns: 1)` 后重新发送，thread ID 不变。Paseo 本功能必须直接调用该路径，明确禁止复用现有 fork-first rewind。 | 是                       | 支持     |
| Claude                 | Paseo 目前只能调用 SDK `forkSession()` 或创建 fresh session，并会 rebind 到新的 `sessionId`。                                                                   | 否                       | 不支持   |
| Pi                     | `ctx.navigateTree(targetUserEntryId, { summarize: false })` 对用户节点自动把 leaf 移到其 parent；首条根消息会 `resetLeaf()`，且 session file/ID 不变。          | 是                       | 支持     |
| OMP                    | 注入 Paseo 私有 extension command 调用 `ctx.navigateTree(targetUserEntryId, { summarize: false })`；OMP `16.3.9` 与 `17.2.5` 均在原 session file 内移动 leaf。  | 是                       | 支持     |
| OpenCode               | 原生 `/undo` 可恢复 composer，但 `session.revert` 同时恢复/回滚文件 snapshot；Paseo 当前也明确关闭 conversation rewind capability。                             | 身份可保留但文件语义不符 | 不支持   |
| Copilot ACP / 通用 ACP | Paseo capability 为 false，ACP 标准没有可依赖的原 session 历史裁剪契约。                                                                                        | 未提供                   | 不支持   |

事实源：

- 详细上游协议、Codex Desktop/CLI、三方实现和 Paseo 当前基础见[调研报告](../../docs/codex-last-user-message-edit-research.md)。
- 现有 UI 两条独立链路见 `packages/app/src/components/message.tsx`、`components/rewind/*` 与 `agent-stream/view.tsx`。
- Codex fork-first 实现在 `packages/server/src/server/agent/providers/codex/rewind.ts`；Claude session rebind 实现在 `providers/claude/{rewind.ts,agent.ts}`。
- Pi 当前 tree extension bridge 已调用 same-session `ctx.navigateTree()`；传入目标用户 entry 本身即可由上游自动选择 parent/root，无需 Paseo 自行导航到 `parentId`。
- OMP 当前 Paseo `revertConversation()` 调用公开 `runtimeSession.branch(entryId)`；上游 `AgentSession.branch()` 对首条消息执行 `newSession()`，对其他消息执行 `createBranchedSession(parentId)`，都会生成新的 session file/ID，因此该路径不满足本功能，必须明确禁止。OMP 同版本的 `navigateTree()` 才是保留原 session file 的原语，但 RPC 协议未公开该命令，需要通过 `--extension` 注入私有 command bridge。
- 现有真实 rewind E2E 只能证明历史边界和文件行为；本功能还必须新增“原生 session ID 前后相同、没有新增可列出会话”的证据。

### 2.4 最小协议与状态契约

1. `AgentCapabilityFlags` 增加可选字段 `supportsInPlaceEditLastUserMessage?: boolean`。只有 provider 能在原生 session/thread ID 不变的前提下准确删除目标最新用户消息及其后续对话、保留文件并继续发送时才设为 `true`。
2. `AgentTimelineItem.user_message` 增加可选字段 `replayKind?: "text_only"`。该字段仅表示 `text` 是完整、可重放的原始用户输入，不代表当前动态状态下一定可编辑。
3. `replayKind` 只能由 daemon 的 canonical App 用户提交路径在规范化输入后写入：文本非空，且没有 image、attachment 或其他 content block。provider history mapper、导入历史、旧持久化 timeline 和其他无法证明来源的消息不得猜测；字段缺失即不可编辑。
4. App 只在 `server_info.features.inPlaceEditLastUserMessage === true` 后读取 provider capability 和 item 标记。三层条件缺一不可。
5. 新 RPC 暂定为 `agent.edit_last_user_message.request/response`：
   - request：`requestId`、`agentId`、目标 `messageId`、`replacementText`、新的 `replacementMessageId`。
   - response：`requestId`、`agentId`、`ok`、`historyState`（`unchanged | rewound | unknown`）、`replacementStarted`、`failureStage`（`validation | rewind | hydrate | start_turn | null`）、`error`。
6. `ok=true` 只表示 replacement turn 已成功启动，不表示模型回答已经完成；后续成功、失败或取消继续走现有 turn stream。
7. `historyState=rewound && replacementStarted=false` 时，App 将草稿移入当前 composer，并显示“对话已回退但修改后的消息尚未发送”；用户下一次走普通发送，不能再次对已经不存在的目标执行 rewind。
8. provider 调用抛错且 daemon 无法证明远端是否提交时返回 `historyState=unknown`，保留草稿并要求先重灌/重连，不谎报“历史未变”。

### 2.5 daemon 编排边界

1. `AgentManager.editLastUserMessage()` 在同一个 per-agent 操作预约内重新读取权威状态；App 的可见性判断只优化 UX，不参与最终授权。
2. 校验顺序：daemon feature/provider 原位 capability -> session 已加载 -> 无 active/pending run 且 lifecycle idle -> 目标是最新 canonical user message -> `replayKind=text_only` -> 替代文本符合普通发送限制且与原文不同。
3. 预约必须阻止其他 App、MCP、schedule 或多客户端 prompt 插入 rewind 与 replacement 之间。现有 foreground run reservation 应增加“内部消费既有 reservation”的路径，replacement 仍复用标准 `startAgentRun`/stream 生命周期，不旁路 turn 状态、持久化和事件广播。
4. 编辑路径不调用 `AgentManager.rewind()`、`invokeRewindCapability()` 或现有 provider `revertConversation()`。新增 provider 原位方法（暂定 `rewindLastUserMessageInPlace()`），其接口契约要求 persistence handle 不变；active/pending 时直接拒绝。
5. Codex 原位方法只允许对当前 `threadId` 调用 `thread/rollback({ numTurns: 1 })`，并断言响应 thread ID 相同；不得调用 `thread/fork`。Pi 复用现有 tree extension bridge 调用 `ctx.navigateTree(targetUserEntryId)`。OMP 新增 Paseo 私有 extension command bridge 调用同样的 `ctx.navigateTree(targetUserEntryId)`；不得调用公开 `branch` RPC。三个 provider 都必须断言操作前后 persistence handle 相同。
6. provider 原位裁剪成功后必须 force hydrate 并产生新 timeline epoch，再启动 replacement。hydrate 失败时禁止基于旧 timeline 自动发送。
7. replacement `startTurn` 失败时释放预约并返回 `historyState=rewound`；由于当前 session 已原位裁剪，不能假设存在源会话副本用于补偿，草稿恢复和明确状态因此是强制要求。

### 2.6 App 交互边界

- 入口：最新 eligible 用户消息 hover/action 区新增独立 Pencil 图标；非 idle 时不显示。图标有 tooltip 和 accessibility label，不放入或复用 `RewindMenu`。
- 编辑：气泡切换为固定宽度约束下的多行纯文本 editor，预填原文；`Cancel` 不发 RPC、不改 timeline。
- 提交：空白、未变化或 pending 时禁用；点击后保持草稿，直到 RPC 返回 replacement 已启动。
- 并发：进入编辑后若 agent 变为 active，立即禁止提交；daemon 仍会二次拒绝。不得自动 cancel 新 turn。
- 失败：
  - `unchanged`：保留气泡内 editor 和草稿。
  - `rewound`：timeline 可刷新，草稿转入主 composer，显示明确的“尚未发送”错误。
  - `unknown`：保留 session 级草稿，禁止继续编辑/发送，先触发 resync；恢复后由用户确认发送。
- 成功：退出编辑态；replacement user message 和回答完全通过正常 stream/epoch 投影出现，不在 App 手工拼接最终 timeline，也不触发 fork draft、路由跳转或新会话导航。

### 2.7 风险与未知

- Codex 的 `thread/rollback` 已废弃，上游未公布移除版本和日期；首版必须新建直接 same-thread rollback 路径，不能复用现有 fork-first adapter。上游移除后，若没有新的 same-thread API，Codex capability 必须关闭，不能迁移到会复制 thread 的 `beforeTurnId` 后仍宣称原位编辑。
- Claude 当前明确不满足身份约束；除非上游提供 same-session conversation truncate API，否则不能仅靠隐藏新 session ID 打开能力。
- Pi/OMP 可能在同一 session 内保留旧树分支；用户已明确接受该内部历史，只要不新增可列出的 session/thread ID。
- OMP 的 same-session 原语只在 extension context 暴露，当前 RPC 没有 `navigate_tree` 命令；注入 bridge 失败、被 `--no-extensions` 禁用或未能回传结果时必须关闭 capability 或拒绝启动，不能回退到会复制 session 的 `branch` RPC。
- 当前 provider history 只有有损文本投影，无法反证历史消息没有附件；因此旧历史默认不可编辑是有意的兼容限制，不是待修 UI bug。
- rewind + hydrate + start 无法成为跨进程数据库事务，故 response 必须暴露部分成功/未知状态；不能只返回通用 toast。
- 三个 provider 都必须验证 persistence handle 在操作前后、重启、重连和新 timeline epoch 后完全一致，且 session listing 没有新增条目。
- `replacementMessageId` 只能防止同一提交重复投影；provider rewind 已提交但响应丢失仍可能产生 unknown，需要 resync 证据。
- 现有 Rewind 功能保持原样；本任务既不删除也不重定义它，只新增一个身份语义更严格的独立能力。
- `grilling` 结论：未使用；用户已明确排除“复制一个会话”的实现结果。

实施顺序：

1. 先写公共 WebSocket/`DaemonClient` 成功路径 Red，固定 request/response、原位 capability、marker、feature gate 和身份不变量。
