## 1. 目标与完成契约

- 当前理解：仅在侧边栏按状态分组时，`Ready to review` 中已完成且仍未读的 workspace 使用加粗标题和绿色圆点；清除未读后仍留在该状态组，但标题恢复常规字重且不再显示绿点。
- 核心目标：把生命周期分组与未读视觉提示解耦，以 Agent 的 `requiresAttention` 作为未读事实，只改变状态分组中 `Ready to review` 行的标题和状态徽标。
- Done Contract：真实完成会话在未读时位于 `Ready to review`、标题字重为 `600` 且项目图标带绿色状态点；打开并清除未读后仍位于同组、标题恢复 `400` 且状态点消失；项目分组渲染入口不启用该视觉覆盖；定向 Vitest、真实 Playwright、typecheck、lint、目标格式及差异检查通过。

## 2. 范围与事实

- 范围内：App 侧 workspace 未读投影、状态分组行的标题字重与 attention 徽标、精确单测和真实浏览器回归。
- 范围外：`Ready to review` / `Done` 分组规则、Agent attention 清除时机与 RPC、项目分组视觉、其他状态组的标题和图标、协议或 daemon 行为。
- 当前任务单元：为已完成 workspace 保留现有状态归类，同时把未读事实独立投影到状态分组行的两处视觉反馈。
- 轻量评估：`standard`；行为目标单一，但未读事实需从 Agent 索引贯穿到共享行组件，并验证真实的未读到已读转换。
- 已确认事实：`0076` 已定义 resident `idle` 无论已读与否均属于 `Ready to review`；当前状态分组行把 `workspace.statusBucket` 同时用于归类和项目图标徽标，所以已读 idle 仍显示绿点；标题当前固定为 `400`；Agent 快照的 `requiresAttention` 才是已读/未读事实；`workspaceAgentActivity` 已集中按 workspace 建立并以结构共享方式供侧边栏消费。
- `grilling` 结论（如使用）：`N/A`；用户明确限定视觉、转换结果与分组模式。
- 风险与未知：一个 workspace 可有多个未归档根 Agent，未读投影需按“任一根 Agent 要求 attention”聚合，且不能让子 Agent 或项目分组意外改变视觉；字体和徽标需要 DOM/计算样式证据，不能只断言内部布尔值。
