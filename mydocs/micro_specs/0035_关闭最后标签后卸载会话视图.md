## 1. 目标与完成契约

- 当前理解：关闭 workspace 的最后一个 root-agent 标签时，不再自动补空白 agent，也不归档会话；客户端应请求 daemon 关闭该 agent 的 provider runtime，保留未归档的 Paseo identity、timeline 与 persistence handle，再卸载当前 workspace 视图。侧边栏继续保留该会话，重新点击后以同一 agent ID 恢复 provider session。规则必须适用于所有 provider，不按 Codex 特判。
- 核心目标：让用户显式释放 idle/running provider runtime 占用，同时不丢失或归档会话，并在侧边栏可靠区分“runtime 驻留”和“runtime 已关闭”。
- Done Contract：close-only 成功后 agent 保持未归档、生命周期为 `closed`、provider 进程与订阅已释放、没有 replacement draft；侧边栏以非纯颜色的可访问状态呈现 runtime residency；重新点击同一会话后以同一 agent ID 恢复 provider session。旧 daemon 通过单一 capability gate 获得升级提示而非错误 fallback；协议双向兼容、受影响测试、typecheck 与 lint 均通过。

## 2. 范围与事实

- 范围内：新增 provider-agnostic close-only RPC 与 capability；daemon `AgentManager.closeAgent()` 调用链；client API；最后标签关闭与 workspace 卸载；同 ID 恢复；侧边栏 runtime residency 状态；协议、server、app 与真实浏览器回归覆盖。
- 范围外：按空闲时长自动回收、内存用量统计、provider 专属分支、daemon 主进程关闭、archive/delete 语义重写、subagent 关闭策略和通用导航重构。
- 当前任务单元：一个跨协议、daemon 与 app 的生命周期闭环；UI 指示必须消费同一权威状态，不能自行猜测进程存在性。
- 轻量评估：`切换 sdd-riper-one`；任务已触及公共 wire contract、兼容 capability、provider 生命周期和跨模块 UI，超出 Light 安全边界。
- 已确认事实：`AgentLifecycleStatus` 已包含 `closed`；`closed` 表示没有 live provider runtime，且 `ensureAgentLoaded()` 能用相同 Paseo agent ID 恢复 persistence handle。所有 provider 都实现统一 `AgentSession.close()` 契约。当前 `close_items_request` 会 archive，不是 close-only；当前 root-agent 单标签关闭也异步 archive。旧 E2E 已在真实浏览器与隔离 daemon 下确认关闭最后 draft 后又出现 1 个 draft，测试用时 58.6 秒。
- `grilling` 结论（如使用）：未使用；用户目标与最后标签边界明确。
- 风险与未知：需要设计新点分 RPC 和旧 daemon capability gate；close-only 失败时不能先静默卸载；running agent 需要沿用显式确认与失败反馈；stored/live projection 必须一致反映 `closed`。任务 `0034` 正在修改侧边栏 view model 与呈现文件，实施时必须合并其最终改动，不能覆盖。
