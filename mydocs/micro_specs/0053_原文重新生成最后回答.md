## 1. 目标与完成契约

- 当前理解：0036 的最后一条纯文本用户消息编辑器在打开后已经预填原文；当内容没有变化时，`Submit edit` 也应可用。提交后仍在当前 Paseo agent 和原 provider session/thread 内回退最后一轮，并以同一段用户文本启动新的 replacement turn，从而重新生成最后回答。
- 核心目标：只取消 App 与 daemon 的“replacement 必须不同于原文”限制，复用 0036 已实现的 rollback + resend 链路，不改变其资格门禁、失败状态、并发保护和 same-session 身份契约。
- Done Contract：
  - 最新 eligible 消息进入编辑态后，只要 agent idle 且草稿 `trim()` 后非空，即使草稿与原文完全相同也允许提交。
  - App 为原文提交生成正常的 `agent.edit_last_user_message.request`，其中 `replacementText` 保持原文，`replacementMessageId` 仍是新的消息 ID。
  - daemon 接受相同文本，成功响应仍为 `ok=true`、`historyState="rewound"`、`replacementStarted=true`，provider 原位回退和 replacement 各执行一次。
  - 操作前后 `agentId`、`workspaceId`、tab/route 和 provider persistence `sessionId/nativeHandle` 不变；允许同一 session 内保留不可见历史分支，但不得新增 session/thread ID。
  - 修改后的文本仍可正常提交；空白文本、运行中 agent、非最新消息、非 canonical `text_only` 消息和带附件消息仍不可提交或被 daemon 拒绝。
  - `historyState="unchanged"` 继续只表示失败发生前 daemon 能确认 provider 历史未改变，不被重定义为“replacement 文本未变化”。
  - App model、公共 daemon E2E、App Playwright UI contract、typecheck、lint、format 和差异检查通过。
