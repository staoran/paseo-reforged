## 1. 目标与完成契约

- 当前理解：根异常页的异常详情应可一键复制完整原文，且用户可以直接跨多行拖选详情文本
- 核心目标：在不改变其他代码详情卡片现有分行渲染的前提下，消除根异常详情的复制与跨行选择障碍
- Done Contract：根异常页显示可访问的复制详情操作；触发后剪贴板得到原始多行详情并展示成功或失败反馈；详情以单一可选择文本节点渲染；定向回归测试、typecheck、定向 lint 与格式检查通过，并完成真实 UI 验收

## 2. 范围与事实

- 范围内：`RootErrorFallback` 的详情展示、复制操作与状态反馈；`ScrollableCodeSurface` 的显式 opt-in 多行选择渲染；对应回归测试和必要的根异常页翻译
- 范围外：其他诊断面板、普通代码块、错误处理架构、协议和 daemon 行为
- 当前任务单元：为根异常页建立可重复的 DOM/剪贴板反馈测试，先 RED 后 GREEN 实现最小 UI 修复
- 轻量评估：`standard`；涉及根级 UI、共享展示原语的限定选项、国际化资源与回归测试，但不改变公共协议
- 已确认事实：`RootErrorFallback` 将格式化后的异常字符串传给 `ScrollableCodeSurface`；该组件默认将字符串按 `\n` 拆成多个 `Text` 节点；根异常边界已处于 I18n 和 Safe Area provider 内，但位于 RootAppTree 内的 Toast provider 外；项目已有 `copyToClipboard` 封装和根异常页 JSDOM 回归测试
- 风险与未知：共享组件的默认分行行为可能服务其他界面，因此新渲染方式必须 opt-in；剪贴板 API 可失败，根异常页不能依赖 Toast 作为唯一反馈
