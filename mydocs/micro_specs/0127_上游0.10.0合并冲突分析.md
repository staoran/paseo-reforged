## 1. 分类准则

- **代码冲突**：Git 无法自动合并的文本块，见第 4 节完整台账
- **同源修复冲突**：双方针对同一故障和同一根因给出互斥实现；本次 42 个冲突块中**没有证据支持这一类**
- **真实意图冲突**：双方希望同一发布或设置入口呈现不同结果；当前是版本与变更日志归属、设置导航归属
- **并列编辑冲突**：同一位置增加不同能力，意图可共存；当前是主题 token 和 Codex 测试
- **交互冲突**：文本可自动合并，但跨文件组合可能让 UI、数据或协议行为失真；第 5 节区分已确认问题和待验证风险

相似表象不能直接当作同源修复。上游 `#5394` 修复现代目录缓存中 workspace map 与 cursor 不一致；本地 0125 用当前连接的 Agent 目录来源控制驻留计数。这两项都涉及重连后界面准确性，却修复不同根因，必须保留两者。上游的同一事务基线对 workspace 数据恢复更完整；本地来源门控对 Agent 驻留数字不可替代，不存在可选其一的实现优劣。

## 2. 双方意图

### 2.1 本地 Reforged

1. **独立发布身份**：0119/F42 和 `b61c1941e` 将根包、各 workspace、锁文件统一到 `0.9.2-beta.4`，保留 Reforged 产品名、仓库和更新源；`@getpaseo/*` 仍是内部兼容包名。`CHANGELOG.md` 记录 Reforged 的 beta 发布，不代表上游官方发布。
2. **Activity 可读性**：0121/F07、`9e8ecf8be` 按 Codex 显式 final phase 折叠整轮过程；`autoExpandActivity` 是独立持久化开关，默认关闭，九种语言已有文案。本地在旧 Appearance 的“详情级别”组加入开关。
3. **模式风险色**：F19、`71ecb7a04` 增加亮/暗模式的 `modeDanger`、`modeModerate`、`modeAcceptEdits`、`modePlanning`，供权限模式控件使用，不能被通用状态色替代。
4. **Codex 过程与重试**：F03/F07/0121 在 Codex adapter 保留 retry 状态、phase 和迟到完成顺序；冲突测试块验证 retry 只属于当前根回合且不写入 timeline。
5. **Agent 驻留与回收**：0124/0125 提供已读/工作状态、只关闭 idle runtime 的 RPC、目录来源门控及驻留数量，要求断线或目录未同步时不显示旧计数。

### 2.2 上游 Paseo

1. **官方 0.10.0 发布**：`c481ecf3e` 将所有 workspace 包及内部依赖升级到 `0.10.0`，`dfc9add77` 整理稳定版变更日志；`c906c2f4a` 引入 OpenCode v2 与 `@opencode/client`，`c7e7e52b0` 更新 Nix 依赖哈希。上游版本号和日志表达其官方发布事实。

### 4.1 Appearance 三块必须一起解

上游移走了旧 `SettingsCard`、`SettingsSwitch`、`SidebarNavSection` 等 Appearance 依赖，新的 `ChatSection` 已持有推理展开、工具详情和 Chat Outline，`settings-screen.tsx` 负责 Chat 与 Sidebar 页面导航。若机械选本地的 21-23，除设置重复外，旧引用还可能因 import/路径消失导致编译失败。正确结果应是 Appearance 只保留主题、字体等外观内容；Chat 的详情卡片新增唯一的 Activity switch，且不改 `autoExpandActivity` 默认值、存储或 Activity 展示行为。

### 4.2 Theme 与 Codex 的共同实现取舍

Theme 双方都想让状态有清晰语义，但本地颜色表达**权限风险**，上游 tint 表达**状态 badge 背景**，不是同一 bug 的两个修法。上游 tint 从已有状态色计算，适合 badge；本地独立风险色适合权限模式。Codex 测试也分别检验 retry 时序和自定义 provider 会话过滤，任何一方的测试都不能代替另一方。

## 6. 解决顺序与验收

1. 以 D1 固定一个 fork 版本，将全部 12 个 manifest、内部依赖和 lock 中的 16 个版本冲突块统一；保留上游 OpenCode v2 依赖图。按 D6 重算 Nix hash，而非选一侧旧值。
