## 1. 目标与完成契约

- 当前理解：在 Electron 工作区标题栏的“打开”下拉菜单中增加可用的 Windows Terminal，并纠正截图中 VS Code Insiders、DataGrip 仍显示通用终端占位符的问题。
- 核心目标：用户可从当前 workspace 一键打开外部终端，且菜单中的已支持应用使用与目标一致的图标。
- Done Contract：Windows Terminal 已安装时菜单出现 Terminal 目标，包括通过 WindowsApps 应用执行别名提供 `wt.exe` 的标准安装；选择后以 workspace 绝对路径作为 `wt -d` 启动目录；VS Code Insiders 与 DataGrip 使用各自应用图标；runtime/注册表定向测试、真实本机 gate、桌面端 typecheck、全仓 typecheck/lint 和目标格式检查通过。

## 2. 范围与事实

- 范围内：桌面端 editor-target 注册表、Windows Terminal 目标、相关图标资源、注册表定向测试。
- 范围外：Paseo 内置 terminal tab、非 Windows 外部终端、其它仍使用占位图标的编辑器、标题栏布局和会话恢复逻辑。
- 当前任务单元：一个 Windows 外部打开目标和两个截图可见的图标修正，可独立验证和交付。
- 轻量评估：`升级 standard`；涉及桌面进程、资源打包和测试多个文件，但不改变公共协议或数据。
- 已确认事实：菜单由 `packages/desktop/src/features/editor-targets/registry.ts` 提供目标；Windows Terminal 的标准 `wt.exe` 可由 `where.exe` 和 PowerShell 解析，`fs.accessSync(F_OK)` 成功，但 Node `fs.existsSync()` 跟随 WindowsApps 特殊链接时因 `EACCES` 返回 `false`，导致产品真实 `resolveCommand(["wt"])` 返回 `null`；Context7 的 `/microsoft/terminal` 官方资料确认 `wt -d <absolute-path>` 设置新标签页启动目录。
- `grilling` 结论（如使用）：未使用。
- 风险与未知：可访问性 fallback 只能用于 WindowsApps `.exe` 执行别名，不能放宽其它命令或 workspace/file 路径校验；Windows Terminal 未安装时仍不得显示入口；修复后需用真实本机 runtime 和 Electron 菜单复核。
