## 1. 目标与完成契约

- 当前理解：异步压缩/解压会改变完成时序；现有 encrypted relay socket 只按估算长度检查 bufferedAmount，没有 prepared-frame 或 receive reservation。
- 核心目标：把最终 wire bytes、出站 FIFO、入站 FIFO 和物理高水位绑定到同一 transport seam。
- Done Contract：
  - 每个应用帧只 prepare/encrypt/encode 一次；发送顺序与调用顺序严格一致，confirm、pending backlog、实时帧不乱序。
  - 发送前按最终 Base64/binary wire bytes 检查单帧 32 MiB 与物理 64 MiB high-water；异步准备期间按实际待处理 bytes 预留，不以旧估算绕过。
  - 接收入站先按 raw wire bytes 预检，再 decode/decrypt；当前项与等待 FIFO reservation 合计不超过 64 MiB。
  - send/decode/close/error 任一失败释放 reservation、关闭当前连接且不交付半成品；legacy path 保持原行为。
  - direct WebSocket 不受 relay queue hint 影响。

## 5. 执行与变更记录

- 实际改动：daemon factory 与 channel 共享 64 MiB raw receive budget，握手 backlog 和 framed application decode 使用同一 FIFO/reservation；prepared frame 校验 mode、opcode 表示、metadata 和实际 wire 长度后只写一次；encrypted relay socket 仅在 framed-v1 启用异步 prepare、调用序 FIFO、32 MiB 排他单帧限制以及 physical/preparing/prepared 三类字节的 64 MiB 合并门禁，任一失败 fail closed。
- 偏差与用户决策：`bufferedAmount` 继续表示底层 WebSocket 已接受的 physical bytes；尚在 prepare/FIFO 的 reservation 由 encrypted socket 内部参与两次 capacity check，不向上层重复暴露，避免同一 wire 被 physical backstop 二次计数。legacy channel 保留原估算、发送错误上抛但连接保持 open 的行为。
