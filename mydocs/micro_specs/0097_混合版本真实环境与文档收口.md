## 1. 目标与完成契约

- 当前理解：本地 RED/GREEN 不能证明 production relay 透明转发、弱网收益、Hermes 解压、混合版本回退或文档事实一致；这些是 Spec 0084 的最终发布门禁。
- 核心目标：在所有实现 tickets 完成后执行真实环境验收、兼容矩阵复核、安全/架构/性能文档同步，并决定是否收口 0084。
- Done Contract：
  - new/new、new/old、old/new、framed Base64/binary、无 codec、confirm mismatch、legacy fallback 在真实/定向环境通过。
  - production relay 只透明转发两种表示；32 MiB 单帧、64 MiB physical/receive budget、错误关闭和顺序门禁通过；不修改外部 Elixir relay。
  - 2 Mbps/150 ms、10 Mbps/80 ms 弱网 profile 的 timeline/10 MiB 文本下载达到父 Spec p50/p95 目标；实时 terminal/agent_stream 回归不超过阈值。
  - Hermes 1 MiB/4 MiB decode p95、无 OOM/错序；失败时按 Spec 移除 `deflate-raw` advertisement，而不关闭 framed identity。
  - 更新 `SECURITY.md`、`docs/architecture.md`、`docs/terminal-performance.md`、`public-docs/configuration.md`、配置 JSON schema 和父 Spec/任务总表；记录旧 binary 回退需删除 transport block。
  - 只有全部证据满足后才将 0084 标为完成；外部 relay 不透明或真机门禁失败时保留明确阻塞，不静默放宽策略。
