## 2. 范围与事实

- 范围内：Windows drive file URL pathname 行号解析；Web/Electron CodeMirror 的目标行 decoration；Markdown Preview 与 Source 模式边界；现有真实助手链接 E2E 的模式与视觉行为断言。

- 当前任务单元：修复同一用户操作中的 parser 与 Web/Electron 定位反馈；不延续或改写历史任务 `0011`。
- 轻量评估：`升级 standard`；仍是边界明确的单一工作流，但扩展为 parser、CodeMirror 状态/样式和 Browser E2E 共五个文件。
- 已确认事实：截图中的预览错误目标以 `EasyLink.Entity.csproj:31` 结尾；当前 `parseFileProtocolUrl()` 只从 hash 调用 `parseLineFragment()`，不会拆 pathname 的 `:31`。
- 已确认事实：最小只读复现返回 `path=E:/.../EasyLink.Entity.csproj:31`、`lineStart=undefined`；现有 `parse.test.ts` 仍为 `40/40` 通过，说明这是测试覆盖缺口。
- 已确认事实：老项目提交 `872c59f16` 提供了“保留编码结构、复用既有行号 parser”的实现先例，但其 `parseFileProtocolUrl()` 分支同样未直接覆盖 pathname 尾部行号，因此不能整段照搬。
- 已确认事实：老项目静态 file pane 对单行与行范围统一应用 `accentBorder` 背景；当前静态预览仍保留该行为。
- 已确认事实：当前 Web/Electron 可编辑源码使用 CodeMirror；单行导航 dispatch `anchor=head=line.from`，而 `.cm-activeLine` 被显式设为透明，因此只滚动和移动光标，不产生背景。
- 已确认事实：提交 `cb6d2f145` 的 E2E 只断言第 42 行可见和光标位置，没有断言背景；提交 `4bda2dfea` 先前已将普通 active-line 背景设为透明。
- 已确认事实：`FilePreviewBody` 的 `isMarkdownFile` 额外要求 `!location.lineStart`；parser 开始正确返回行号后，Markdown Preview 因此绕过 `MarkdownRenderer` 并走静态代码分支。`markdownMode` 本身没有被导航切换为 Source。
- `grilling` 结论（如使用）：`N/A；目标、范围和复现输入明确。`
- 风险与未知：目标 decoration 必须在重复导航时重设、无行号位置时清除，并随文档变更映射；不能借此改变用户手动移动光标或编辑文本的 selection 语义。
