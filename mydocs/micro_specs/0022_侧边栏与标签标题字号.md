## 1. 目标与完成契约

- 当前理解：Interface size 设置为 16 时，只有消费 `theme.fontSize.sm` 的区域是 14，其他区域分别消费 `xs/base/lg/xl`；用户确认这种 Interface 字号梯度没有意义，不接受只修几个标题 surface。
- 核心目标：让用户指定的 Interface size 成为全部 Interface 文本 token 的实际 px；保留 Interface / Workspace / Code 三条独立字体轴，但只有 Workspace 保留语义字号梯度。
- Done Contract：11/16/20/24 下 `theme.fontSize` 除 `code` 外的全部 token 都精确等于 Interface 设置值，`fontSize.code` 与 `workspaceFontSize` 行为不变；默认主题同样满足统一合同；代表性 Web/Electron 与 Native 紧凑布局无裁切、重叠或不可操作控件。

## 2. 范围与事实

- 范围内：Interface 默认 theme、运行时 appearance mapper、共享 control geometry、侧边栏固定文字行高、既有 typography unit/E2E、Interface 字号长期文档合同。
- 范围外：storage/clamp、Workspace/Code 字号梯度、字体族、未被目标 E2E 覆盖的逐组件布局重构和新的 typography abstraction。
- 当前任务单元：全局 Interface font-size 合同；`parent spec=N/A`。
- 轻量评估：`deep`；实现集中在共享 theme mapper，但会改变约 487 个 Interface token 消费点并覆盖 Web、Electron、iOS、Android。
- 已确认事实：`uiFontSize=16` 原样保存并传给 `applyAppearance()`；`theme.ts:444-454` 定义 `sm=14/base=16`，`apply-appearance.ts:23-55` 计算 `sm=round(14*size/16)`。
- 消费事实：当前源码有 `xs=183`、`sm=235`、`base=50`、`lg=15`、`xl=4` 处 `theme.fontSize.*` 消费，因此“仅部分区域 14”是旧梯度合同的直接结果，不是 clamp/CSS 失效。
- 历史事实：`0009` 明确保留 UI/workspace ramp，目的是在用户调整基准字号时维持视觉层级；它是跨平台设计系统选择，不是移动端专用适配。
- 平台事实：Web/Electron/Native 都通过相同的 Unistyles runtime theme patch 消费 `theme.fontSize`；Native 同样会受统一合同影响，且 24px 时固定高度控件的裁切风险高于 Web。
- 已选新合同：在默认 theme 和 `applyAppearance()` 的共享边界把所有非代码 Interface token 映射为同一个 `uiFontSize`；不逐组件替换 `sm -> base`，Workspace ramp 与 Code absolute size 保持不变。
- E2E 根因：激活 Workspace 标签会合并两个都依赖 Theme 的 Unistyles 样式；`react-native-unistyles@3.2.4` Web 的 `deepMergeObjects` 把第二次 `uni__dependencies: [Theme]` 合并为非数组对象，监听器随后丢弃该依赖。损坏结果的计算哈希 `unistyles_1qbnjli7y2m` 与浏览器节点完全一致，因此标签停留在挂载时的 16px；locator 与 2 秒更新延迟均已排除。
- 风险与未知：浏览器 zoom、系统 text scale 和字体 x-height 仍影响“看起来多大”；自动验收以 computed px 为准，iOS/Android 另做 11/24 裁切 smoke。
