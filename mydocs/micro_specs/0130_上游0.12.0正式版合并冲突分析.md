### 1.2 分类定义

| 分类           | 判定标准                                                  | 处置原则                                                      |
| -------------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| 同源修复冲突   | 同一个原始 patch 通过 cherry-pick 或等价 patch 在两侧相遇 | 去重，只保留一份；用 patch 证据确认，不凭标题相似判断         |
| 同缺陷独立修复 | 双方解决同一用户问题，但来源、覆盖面或实现不同            | 比较边界和测试，选择更完整的一方并迁移另一方独有覆盖          |
| 同目标实现演进 | 双方目标一致，上游把职责迁到新架构或扩大覆盖              | 以上游新边界为骨架，把本地已发布行为接入新边界                |
| 真实意图冲突   | 最终产品合同或发布身份不同，不能原样同时成立              | 先按“继续合入上游”还是“发布 Reforged”确定主合同；没有默契叠加 |
| 派生物冲突     | 版本、lockfile、Nix hash 等由最终输入计算出来             | 不手工挑一侧；选定 manifest 后重新生成并复核                  |
| 语义冲突       | Git 能自动拼接，但行为、lint、交互或测试合同会互相覆盖    | 按行为审计处理，并在验收矩阵中留证                            |

本次没有通过 `git log --cherry-mark` 发现本地与目标之间的 patch 等价对。因而“同源修复冲突”严格口径为 **未发现**；以下出现的同问题修复均标为“同缺陷独立修复”或“同目标实现演进”，不能声称是 cherry-pick 重复。

本轮也没有确认“双方各自修了同一个具体缺陷、现在必须选一份”的代码块。C22/C24 是不同测试插入同一位置，C25 是本地注释碰到上游新增函数，C23 是本地功能字段碰到上游持久化优化。目标相近不等于修复同源，也不等于一方功能可以替代另一方。

## 2. 先决决策

### 2.1 上游 `0.12.0` 与 Reforged 版本不能混为一个事实

上游 `cafe4b01c` 的 `0.12.0` 是上游产品的正式发布号。当前根 `package.json` 和各 workspace manifest 是 Reforged `0.12.0-beta.1`，并且 `docs/release.md` 明确要求保留 Reforged beta 历史、身份和更新源。

因此本次“继续合入”建议采用以下边界：

1. 代码、测试、插件资源和正式版修复合入上游目标 SHA。
2. 在没有单独发布决策前，保留 Reforged 的产品身份和当前 beta 版本合同。采用上游的版本字符串不会自动改变 app ID 或更新源，但会改变预发布状态、版本排序和 release notes 的对应关系。
3. 旧 beta.1 已交付。后续若打包或发布这次集成，建议单独增加 `0.12.0-beta.2`，经验收后再决定是否晋级；这是候选建议，本轮不定版。若选择 Reforged stable，则统一生成版本、changelog、lockfile、Nix hash、产物和更新清单。

本轮分析不需要等待版本选择。实施时用 `V` 表示最终 Reforged 版本；保留 beta.1 的工作版本值不代表可以覆盖已有 beta.1 产物或改写它的 release notes。C03–C21、C26–C41 中的所有版本字段最终统一为 `V`。

### 2.2 代码选择原则

- Markdown、文件面板、布局持久化和 Agent selector 采用上游新职责边界，保留本地已发布行为和专门回归。
- 关闭历史、普通标签关闭、手机 preview sheet、Activity 本地折叠和选区 Ask 是 Reforged 的产品合同，不能被上游相邻重构删掉。
- 新增 lint 规则属于上游质量合同；本地命中的四个文件不能靠永久扩大例外列表绕过，优先迁移到项目已有交互原语。
- 协议和 Usage 仍按追加兼容处理。上游新能力可以增加，但不能删除本地已经发布的旧 namespace、resolver 或错误 envelope。
