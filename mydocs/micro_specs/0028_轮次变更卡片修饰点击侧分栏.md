## 1. 目标与完成契约

- 当前理解：保持轮次文件变更卡片现有普通点击行为；Web 上按住 `Ctrl` 或 `Cmd` 点击文件时，像会话文件超链接一样在右侧 pane 打开 Changes 差异并聚焦该文件。
- 核心目标：让用户无需离开当前会话 pane，即可并排查看本轮某个文件的 working diff。
- Done Contract：普通点击仍在当前 pane 打开聚焦后的 `working_diff`；`Ctrl`/`Cmd` 点击使用 `side` disposition，桌面端按既有相邻右 pane/新建右 pane规则打开，移动端保持现有主 pane 回退；定向组件测试、相关静态检查和格式检查通过。

## 2. 范围与事实

- 范围内：变更卡片文件行的 Web 修饰点击识别、回调打开方式、pane 内 working-diff 导航及 side-pane 放置接入。
- 范围外：浏览器原生新标签页、历史 diff、working-diff 身份模型、移动端新增手势、会话超链接本身的行为修改。
- 当前任务单元：轮次变更卡片修饰点击侧分栏；`parent spec=N/A`。
- 轻量评估：`standard`；UI 行为本身很小，但需要贯通卡片、agent panel 与 workspace pane 上下文。
- 已确认事实：会话文件超链接把普通点击映射为 `OpenFileDisposition="main"`，把 `Ctrl`/`Cmd` 点击映射为 `"side"`；workspace 已使用 `resolveSideFileOpenPlacement()` 在桌面端聚焦相邻右 pane 或新建右 pane，移动端回退主 pane；`working_diff` target 已支持 `focusPath/focusRequestId`。
