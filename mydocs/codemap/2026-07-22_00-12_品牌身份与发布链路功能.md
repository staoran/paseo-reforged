# 品牌身份与发布链路 CodeMap (feature)

> Historical snapshot from 2026-07-22 after the E3 scope reversal. The remote replacement and deletion plan recorded below is obsolete and must not be executed or treated as current authorization. Source/config/tests win on drift; `mydocs/specs/0001_重命名与发布迁移.md` owns the migrated historical contract, and any new release or remote write requires a new task and approval.

## 1. Orientation

- Goal: 定位一个发行名称如何从 manifests/config 传播到移动安装身份、桌面安装器、更新器、网站下载和 GitHub release，并标出 Git remote 覆盖边界。
- Current State: 工作树已迁移为 `Paseo Reforged` / `sh.paseo.reforged*` / `staoran/paseo-reforged`，并完成本地验证；Git `origin` 和目标远端尚未变更。
- Remaining Planned State: 先用旧身份的已提交 `main` 重置并清空目标其他 refs/Releases；之后另行提交 Reforged 工作树，运行 Node 22/CI 发布门禁并完成 beta 验收。
- Scope: release identity、installer、updater、external project links、asset discovery、release workflows、remote main replacement。
- Non-Scope: CLI `paseo`、`~/.paseo`、scheme、npm scope、protocol/IPC、运行时服务域名、全面视觉品牌重做。
- Confidence:
  - confirmed: 当前入口、参考实现、目标 GitHub/EAS 状态和主要平台合同已核验。
  - locally verified: Mobile、Desktop、Updater、Website、Nix、release scripts/workflows 和 build-only Docker policy 已实现并通过 E1/E2 Review。
  - planned: Git remote replacement、真实 beta CI/Release 和外部安装验收受独立 checkpoint 约束。
  - unknown: 新 App Store/Play listings、正式 macOS signing、fork Cloudflare 部署尚未 provisioning。

### Node: Git Remote Replacement

- Type: `high-risk effect`
- Status: `planned / separately gated`
- Purpose: make current repository target `staoran/paseo-reforged`, replace remote `main` with current committed local main, and delete every other branch/tag/Release selected in the frozen manifest。
- Current Facts:
  - local origin: upstream `getpaseo/paseo.git`。
  - investigation-time target main snapshot: `71cba052...`，执行前必须刷新，不能直接用作 lease。
  - target also has two feature branches, 152 tags, and Release `356029014` with 24 assets (~2.15 GiB)。
  - local committed main `679d7131...` does not include the uncommitted Reforged migration。
- Required Flow:

```text
fresh frozen refs/release snapshot
  -> atomic explicit-lease push: HEAD -> main + delete 2 branches + delete 152 tags
  -> verify only main remains and tags are empty
  -> delete Release 356029014 by API id
  -> verify Releases are empty
  -> preserve old origin as upstream and point origin to target
```

- Forbidden: `--mirror`, bare `--force`, implicit tracking lease, automatic deletion-scope expansion after snapshot drift。
- Failure Handling: any frozen-object mismatch stops before writes; Release API failure after the atomic ref push reports a partial state and retries only the remaining Release deletion。
- Validation: target has exactly `main=679d7131...`, zero tags, zero Releases, and no other heads。No new backup/recovery branch is created by user direction。
