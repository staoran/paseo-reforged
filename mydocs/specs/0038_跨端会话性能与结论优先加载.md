## 1. 目标、范围与完成契约

- 背景/问题：长会话、持续流式、大量持久化 Agent、多 Host 和会话导入仍存在可静态确认的线性工作量。upstream `v0.3.0-beta.4 -> v0.3.0` 新增 History 搜索后，用户更容易打开 stored/archived Agent，但 stable 只搜索 Agent 元数据，不搜索 transcript，也没有解决 Timeline 冷恢复、折叠渲染、缓存写放大或元数据启动扫描。
- 最终目标：降低默认路径中的序列化、存储、provider hydrate、网络、布局、DOM、订阅和元数据解析工作，同时保持 canonical history、分页、实时追平、权限/问题/失败状态和旧 daemon 兼容。
- 当前任务单元：维护父子边界、stable 影响、实施顺序和集成合同，并汇总已经按子 Spec 归属完成的产品实现与验证。
- 范围内：Replica cache、Activity render model、durable Timeline、completed/stored Agent 快速路径、Windows 面板驻留、导入发现、Agent metadata catalog、共享 App seam 的 Web/Native 正确性以及相关协议兼容。
- 范围外：0039 的耗时/CPU/RSS 基线体系、移动端真机性能结论、transcript 搜索、数据库替换、Native 列表调参、发布、commit、PR，以及父 Spec 自行新增未归属产品行为。
- Done Contract：
  - 0040-0046 分别满足其收窄后的结构合同和定向测试，不以未稳定的墙钟时间作为门禁。
  - 折叠 Activity 在共享 Web/Native render model 中每轮只有一个 row，重型内容在不可见时不物化。
  - 持续流式不再每 `750ms` 触发 Replica cache 全量写；dirty revision、写中再变脏和失败重试不丢状态，Web/Native lifecycle 均有定向正确性验证。
  - durable Timeline 可重启恢复并支持 bounded tail/before/after；只有 complete generation 与 StoredAgentRecord `timelineRevision` 匹配时才跳过 provider history。
  - running/gap recovery 继续完整追平；summary/detail 使用独立 display/cursor lane，不能跳过 canonical seq，也不能隐藏 permission/question/failure。
  - ordinary 重型视图驻留和 inactive Agent 订阅有明确上限；modified file 保持挂载并作为显式 correctness exception，不因本任务驱逐而丢失状态。
  - 导入发现使用与 imported count 无关的单次 bounded snapshot；并发相同导入复用同一结果，transaction marker 保证 commit/recovery；完整 job 协议只有出现必要证据才恢复。
  - AgentStorage 正常启动只读 marker/catalog；所有生产 `list()` 消费面迁移到 metadata/index/lazy-get seam，History 仍对完整轻量候选集计算全局 Top K。
- 失败或回炉方式：任何 durable、cursor、generation 或草稿恢复合同失败时回退对应子项，不以缓存、部分排名或 UI 动画掩盖数据不完整。
