## 已确认问题

1. Windows 浏览器形态路径未归一化：`/E:/Code/...` 被当作 POSIX 绝对路径，文件预览目标退化为 `cwd="/"`；在 Windows 上，目标盘符随后落在所选 root 外并报 `Access outside of workspace is not allowed`。
2. 工具调用卡片绕过统一 parser：`file.ts:93` 被直接交给 inline path normalization，`:93` 留在文件名中；现有 parser 本可拆出文件路径和 `lineStart=93`。

根因分别位于 App 的 canonical file location 入口和工具卡片打开接线。App 有意允许 workspace 外的绝对文件，并为其选择文件系统 root；服务端只保证请求路径的词法路径和 realpath 不逃逸请求传入的 `root`。本任务不得收窄该产品能力，也不得放宽 root scope。
