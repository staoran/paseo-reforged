## 1. 目标、范围与完成契约

- 背景/问题：App 当前打开、重连和重新可见时已经请求 bounded projected tail，因此“把初始递归 `after` 改成 tail”不再是待办；但 server 在返回该页前仍会 `ensureAgentLoaded()`，stored-only Agent 可能恢复 provider 并全量 `streamHistory()`。投影遇到 tool call 或切断的 assistant/reasoning 时还可能读取 `limit:0` 的完整 live Timeline。
- 最终目标：有 0042 durable 数据的 stored/completed Agent 不启动 provider runtime 即可显示最近用户问题与最终回答；默认折叠 Activity 不读取或传输正文，展开时只读取目标 turn；running/gap recovery 继续完整追平。
- 当前任务单元：只贯通 durable read、最小 wire capability、delivery mode 和局部 Activity detail UX。
- 范围内：stored payload + durable timeline read、summary/detail capability、AOT-safe wire、client method、completed fast path、独立 summary/detail display lane、按轮 detail cache、局部 loading/error/retry，以及共享 reducer/render model 的 Web/Native 正确性测试。
- 范围外：0042 file Adapter、0040 fold row 聚合、修改 History 搜索范围、停止 running `hasNewer` catch-up、Native FlatList 调优或真机性能结论。
- Done Contract：
  - durable completed Agent 的首个可用 render 不调用 provider resume/`streamHistory()`，也不先把全部 rows 放入 live memory。
  - summary 只含用户消息、`final_answer` 和 Activity descriptor，不含 reasoning/tool/intermediate assistant/todo/error/compaction 正文；未展开前 detail request 和 Activity payload bytes 均为 0。
  - 展开只按目标 descriptor 的 epoch/revision/source ranges 做正整数 bounded read；失败和重试局部化，其他 Activity、final 与滚动锚点不被阻塞。
  - summary/detail 只进入独立 display lane，不安装 canonical range、不推进 `ViewedTimelineSync` cursor；切回 legacy/running 路径时由普通 canonical tail 原子替换该 display lane。
  - running、gap、permission、question、failed、canceled 和没有 durable/可靠 phase 的 Agent 继续走现有 projected timeline fallback。
  - 旧 daemon/client 双向兼容；新 capability 只在完整 fast path 可用时宣告。
- 失败或回炉方式：durable coverage、completion 或 cursor 任一不可靠时返回 legacy projected tail；不得以 `idle` 或文本位置猜测 completed，也不得跳过 canonical seq。

### 1.1 最小任务单元判断

- 为什么当前任务单元足够小：只交付一个“stored/completed durable read”用户路径；存储内部和 render 聚合分别归 0042/0040。
- 验证证据：session timeline handler、protocol/client、`ViewedTimelineSync` ports 和 browser 会话视图均有稳定 seam。
- 模型可自主决定的范围：只能调整下述 optional projection 字段的内部 TypeScript 命名；不得改为第二套 RPC、让 projection response 进入 canonical reducer，或同时维护两套等价 summary 协议。
- 拆分决定：`Accepted`。

### 1.2 stable 影响与范围调整

- stable History 搜索只检索 workspace/title/branch/project 元数据，不检索 transcript；它会把更多 stored/archived Agent 暴露为可打开结果。
- `ViewedTimelineSync.fetchUntilCurrent()` 的 `hasNewer` 递归现在服务真实 gap/running catch-up，不能按旧计划整体删除。默认 start 已是 `planTimelineTailFetch()`。
- server 的真正阻塞点在 `handleFetchAgentTimelineRequest()` 先调用 `ensureAgentLoaded()`，以及 projected page 为保持 tool/assistant 边界可能回退完整 timeline。
- 必要性结论：`保留但显著收窄`。删除重复的初始 tail 改造，先解决 stored/completed 零 provider start；零 Activity payload 仍未实现，因此 summary/detail 目标保留。
- 实施原则：复用现有 `fetch_agent_timeline` request/response envelope，保留既有 `projection: "projected" | "canonical"` 字段不变，通过 capability-gated optional discriminated `projectionRequest`/`projectionPayload` 表达 summary/detail；新字段缺失时严格保持既有 projected/canonical 语义，不新增第二个 RPC 或通用 query layer。

- stable 事实源：0056、`agent-history-search.ts`、`use-agent-history.ts`。

- 依赖：0042 提供 durable canonical read；0040 提供 fold row/detail 消费 seam。

### 2.2 已确认事实

- App 首次和可见性 catch-up 默认请求 bounded projected tail；旧 cursor 的 recursive-after 已不是初始打开策略。
- `handleFetchAgentTimelineRequest()` 仍先加载 Agent，再从 in-memory store fetch。
- `selectProjectedTimelineProjection()` 遇到 tool call 或边界投影时可能执行 `fetchTimeline(... limit: 0)`。
- 现有 protocol 没有 summary/detail capability，默认 tail 仍可能携带最多数十个 bounded tool details。
- 0042 的 `AgentTimelineCoverage` 只有 active/working/eligible，没有独立 completed-turn marker 或持久化 `turnId`；0042 只在显式 `turn_completed`、provider history 完整读取或受控 close drain 后提交 generation，失败/取消/错误会留下 incomplete/working 状态并清除 record revision。
- 因而 fast-path completion 以“0042 eligible committed generation + StoredAgentRecord revision 精确匹配 + 本次 bounded reconstruction 得到可靠 `final_answer` turn”为证明，不从 provider 名称、`status=idle`、`archivedAt`、文本位置或未持久化的 provider `turnId` 推断。

| B    | 从 eligible committed coverage 派生独立 summary + Activity descriptors，并按 epoch/revision/activityId/ranges 获取 detail     | 必做，用于满足零 Activity payload；复用现有 fetch envelope |

#### Fast-path eligibility

以下条件必须同时成立，否则同一 request 直接返回现有 legacy projected tail：

1. `AgentManager.getAgent(agentId) === null`，`AgentStorage.get(agentId)` 存在且 `lastStatus` 仅为 `idle` 或 `closed`；live/running/initializing/error Agent 不走 fast path。
2. stored record 有 `timelineRevision`，且没有非空 `lastError` 或 `attentionReason === "permission"`；question 复用 permission request/attention 通道，无法由这些持久化字段证明已解决时 fail closed。
3. `getDurableTimelineCoverage(agentId, { expectedRevision })` 返回 `eligible === true`、`active.valid === true`、`working === null`，且 active epoch/revision 与 record 精确匹配。
4. bounded reconstruction 能从 durable rows 找到以 canonical `user_message` 开始、含 projected `assistant_message.phase === "final_answer"` 的完整最近 turn；扫描在 turn 中间达到上限、epoch/gap/cursor 不连续或没有可靠 final phase 时 fail closed。
5. 0042 的 committed generation 是生命周期完成证明；0043 不新增第二套 marker，不持久化 provider `turnId`，也不把 archive/idle 本身当作完成证明。

`server_info.features.agentTimelineSummaryDetail` 是 daemon 的全局实现能力，只说明 schema、durable read、summary 和 bounded detail 三段代码都存在，不代表任一具体 Agent eligible。每个 summary/detail request 仍逐次执行上述检查；detail 还必须重新核对 epoch/revision/working pointer。新 client 只在 feature 为 `true` 时发送新字段，缺失 capability 时直接使用既有 tail。

#### Wire 与 cursor 决策

- 既有 request `projection?: "projected" | "canonical"` 与 response 必填 `projection` 保持字面和默认行为不变。新增 optional request 字段：
  - `{ projectionRequest: { kind: "summary" } }`
  - `{ projectionRequest: { kind: "activity_detail", epoch, timelineRevision, activityId, sourceSeqRanges, cursor?, limit } }`
- `activity_detail.limit` 是“本页最多读取的 canonical rows”，必须为 `1..200`；`cursor` 必须与 request epoch 相同并位于 descriptor ranges 内。`limit=0` 只保留给既有 canonical fetch，summary/detail 不接受。
- 新增 optional response `projectionPayload` discriminated union：
  - summary：`{ kind: "summary", epoch, timelineRevision, entries, activities, hasOlderTurns }`；`entries` 只含 user/final，`activities` 只含 descriptor metadata。
  - detail：`{ kind: "activity_detail", epoch, timelineRevision, activityId, entries, nextCursor, hasMore, error }`；`entries` 是目标 Activity 的 canonical-entry page，客户端在该 Activity overlay 内累计，最后一页到达前不物化 members；可恢复的 stale/invalid detail 失败写入 `error:string`，成功为 `null`。
- summary/detail response 的既有 envelope 字段保持 schema-valid 但不具备 canonical cursor 含义：`agent=buildStoredAgentPayload(record, providerIds)`、`direction:"tail"`、`projection:"projected"`、`epoch/window=active generation`、`entries: []`、`startCursor/endCursor: null`、`hasOlder/hasNewer/reset/staleCursor/gap: false`；新 client 只消费 `projectionPayload`。summary eligibility miss 返回不带 `projectionPayload` 的完整 legacy payload。
- descriptor 的 `sourceSeqRanges` 按 `startSeq/endSeq` 排序、合并相邻区间并要求非空；`activityId = "activity:" + sha256(epoch + "\n" + timelineRevision + "\n" + canonical-json(sourceSeqRanges))`。detail request 重复携带 ranges，daemon 重新规范化并校验 activityId、coverage window 和每页内容均不含 user/final；该 identity 是跨重连稳定定位，不是第二套 provider turn identity。
- client 增加 `fetchAgentTimelineSummary()` / `fetchAgentTimelineActivityDetail()` 两个 typed convenience method，内部仍发同一 request type；普通 `fetchAgentTimeline()` 保持签名和行为。
- 新 daemon 对没有 `projectionRequest` 的旧 client 始终返回旧 response；新 client 对缺少 capability 的旧 daemon 不发送新字段。summary request 遇到 Agent 不 eligible 时返回不带 `projectionPayload` 的 legacy response；客户端不得伪造 summary。detail request 的 revision/coverage/id/range/cursor 任一失配时返回带同 kind/identity、`entries:[]`、`hasMore:false`、`nextCursor:null`、`error` 非空的 projection payload，outer `error` 保持 null，绝不调用 `ensureAgentLoaded()` 或 provider fallback；只有 transport/handler 非预期异常使用 outer error。

#### Bounded reconstruction

- daemon 常量固定为 `SUMMARY_SCAN_PAGE_ROWS=256`、`SUMMARY_SCAN_MAX_ROWS=4096`、`SUMMARY_MAX_TURNS=20`、`DETAIL_MAX_PAGE_ROWS=200`；后续调整必须有基准证据，不从 request 放大。
- summary 从 committed tail 向前读取，每页 epoch 必须一致、cursor 必须严格后退、seq 必须连续；收集至最多 20 个完整 user/final turns，并继续读到最老已选 turn 的 user boundary。少于 20 turn 且到达 durable minSeq 视为完整；达到 4096 rows 仍停在 turn 中间则 fast-path miss 并走 legacy。
- 对 bounded rows 复用 `projectTimelineRows({ mode: "projected" })` 合并 canonical chunks。每个返回 turn 必须恰有可识别 user boundary 和至少一个 final；user/final 进入 summary entries，其余 projected entries 的全部 canonical source ranges 进入同一 Activity descriptor。没有 Activity rows 的 turn 不生成 descriptor。
- detail 按规范化 ranges 和 optional cursor 从小到大消费最多 `limit` 个 canonical rows；跨 range 时跳过 descriptor 外 seq，`nextCursor` 是本页最后一个已消费 canonical seq，`hasMore` 只表示 descriptor ranges 内仍有 row。daemon 校验每次 durable fetch 的 epoch、revision、严格 cursor 进展、连续性及 row 属于目标 ranges；客户端按 seq 去重累计 raw entries，仅在 `hasMore=false` 后一次调用既有 canonical hydration 生成 members，从而不在分页边界拆坏 assistant/tool lifecycle 合并。
- `hasOlderTurns` 只说明 summary window 前仍有 durable rows，不是 canonical `hasOlder`。用户显式请求旧历史、chat outline canonical jump 或任何 `before/after` request 时，一次性切回现有 canonical tail/分页路径，不把 summary cursor 当 canonical cursor。

#### Projection display lane

- `SessionState.agentTimelineProjectionLanes` 以 agentId 为 key；lane 保存 summary identity、app-only display items、`canonicalReplacementPending` 与 `activityId -> idle/loading/ready/error` detail state；loading state 还保存本次 local request generation，不写入 `agentStreamTail/head`、`agentTimelineCursor` 或 `agentAuthoritativeHistoryApplied`。
- summary response 由 projection reducer 一次安装。app-only `ActivitySummaryStreamItem` 的最小 shape 为 `{ kind:"activity_summary", id:activityId, timestamp, descriptor, detailStatus, members }`；idle/loading/error 的 `members=[]`，不保存正文。AgentStream model 将它直接投影成 `completed=true` 的现有单一 Activity row，Web/Native 使用同一 row shape，普通 canonical reducer永不产生此 kind。
- 首次展开将对应 key 从 idle/error 置为 loading 并递增 local request generation；分页只追加到该 key。generation、revision 或 activityId 不匹配的迟到 response 丢弃；同一 generation 遇到 payload `error` 才转局部 error。ready 后才物化 members；error 保持 Activity header/final/其他 turn 可用，再次展开或 retry icon 只重试该 key。
- 任一不带 `projectionPayload` 的成功 canonical response，通过一个 Zustand action 同时安装 canonical tail/cursor 并删除 lane，避免空白帧。`ViewedTimelineSync.refreshAgent(agentId)` 是唯一 superseding-tail port；首个 live `agent_stream` 或 running `agent_update` 先把 lane 的 `canonicalReplacementPending` 置 true 再调用该 port，后续事件不重复触发。gap recovery、显式 older/jump 直接使用 canonical request；lane 在成功 canonical response 到达前保持只读，失败则保留 lane 并由既有 retry 状态提示。
- 通用 `fetch_agent_timeline_response` listener 遇到 `projectionPayload` 必须忽略；summary/detail 由发起请求的 await 路径应用。summary tail port 为每个 agent 递增 local request generation，只在 generation 仍当前、Agent 仍非 live、且 lane 未进入 canonical replacement 时安装并解除 initialization；detail 由对应 Activity generation 应用。普通不带 projection payload 的 response 继续现有 reducer/cursor 流程。
- summary/detail await 路径不调用 `processTimelineResponse()`、canonical cursor reducer 或 `recoverTimelineGap()`；`ViewedTimelineSync` 只把成功 summary 视作一次无 `hasNewer` 的可见性 catch-up。effect cleanup、断连和 superseding canonical tail 都使相关 local generation 失效。
- projection lane 的 `hasOlderTurns` 只控制“切换到完整历史”入口；该入口和 chat outline jump 发送不带 `projectionRequest` 的 canonical tail/jump，并由上述原子 action 接管后续 `before` 分页。不得用 summary descriptor 的 seq 构造 `AgentTimelineCursorState`。
