## 7. 远端覆盖研究

### 7.1 为什么禁止 mirror

Git 官方语义：`--mirror` 会镜像 `refs/` 下全部 refs，包括创建、强制更新和删除。当前本地 refs 与目标仓库的两个 feature branches、152 个 tags 不同，mirror 会把“覆盖 main”扩大成远端全 refs 重写。

### 7.2 推荐原子操作

```text
read-only preflight
  -> mirror clone + bundle + checksum
  -> remote recovery branch for old main
  -> preserve old origin as upstream
  -> set origin to exact target HTTPS URL
  -> explicit old-OID force-with-lease for refs/heads/main only
  -> after-ref manifest and SHA verification
```

核心命令形态：

`git push origin HEAD:refs/heads/main --force-with-lease=refs/heads/main:71cba052...`

OID 只是调查快照示例，执行时必须重新读取并替换。若新 OID 不同，停止并重新 checkpoint，不能把 lease 更新成新值后自动继续。

### 7.3 备份层

- 独立 mirror clone：保留目标所有 refs/object，不污染当前工作仓库。
- Bundle + SHA-256：提供离线恢复证据。
- Remote recovery branch：让覆盖前 main 在 GitHub 上立即可访问。
- Before/after manifest：证明非目标 heads/tags 未变化。

GitHub Releases 不只是 branch ref；本任务不删除 release，也不把 tag cleanup 当作覆盖的一部分。

## 8. 官方文档结论

### Electron Builder

- `appId` 是平台应用身份；NSIS GUID 默认由 appId 派生。修改为 `sh.paseo.reforged.desktop` 意味着新安装身份。
- assisted NSIS 的安装目录会受 product filename 影响；`shortcutName` 和 `uninstallDisplayName` 应显式配置，避免只依赖默认推导。
- 第一个 publish provider 决定默认 updater server；packaged `app-update.yml` 会带 provider 信息和 updater cache 相关配置。
- `extraMetadata.name` 可改变 packaged metadata，而不必迁移源码 workspace `@getpaseo/desktop`。

### Expo / EAS

- `android.package` 与 `ios.bundleIdentifier` 决定原生安装/商店身份；更换后是新 app identity。
- `updates.url`、`runtimeVersion` 和 `extra.eas.projectId` 必须与同一个 EAS project 对齐。
- effective config 是验证动态 app config 的必要证据；只看源码字符串不足以证明 production/development variant 生效。
- Context7 当前 EAS CLI 文档（`/expo/eas-cli`）确认：远端 build 解析 app config 时，环境由所选 EAS environment 的服务端变量与 `eas.json` build profile 的 `env` 合并；启动 `eas build` 的 GitHub runner 临时环境不能替代远端 build profile/environment 配置。因此 `EAS_PROJECT_ID` 既要用于 GitHub workflow 的本地 preflight，也必须显式进入 development/production build profile，避免远端 builder 把 OTA 和 `extra.eas.projectId` 解析为禁用/缺失。

### Git

- `--force-with-lease=<ref>:<expect>` 只有远端 ref 精确等于预期 OID 时才允许更新，适合本任务的单 ref 覆盖。
- 普通 `--force` 没有并发保护；省略精确 expected OID 的 lease 依赖 tracking state，不如显式 OID 合同清楚。
- `--mirror` 的删除语义与“保留目标其他 refs”的目标冲突。
